# Product: план автоматического захвата и гильдейской экономики

Дата: 8 ноября 2026 года. Исполнитель: основная Sol; спецификация/план и единственный итоговый read-only обзор: Astra.

**Goal:** реальный бой независимого лицензированного арбитра автоматически передаёт гильдейский ресурсный объект; прежний stock безопасно возвращается прежнему союзу, будущая выработка выдаётся новому через типизированную домашнюю доставку. Включение Product — отдельная неразрешённая здесь операция.

**Architecture:** один extended OutpostAuthority V3/anchor; отдельные guild tables и artifact store; production executor lane + player commander lane; отдельный battle map mirror без personal custody; прежний source/readiness и restore контракт сохраняется с versioned расширением.

**Spec:** [утверждённый C](../specs/2026-11-07-guild-outpost-capture-design.md), [Product addendum](../specs/2026-11-08-guild-capture-product-addendum.md). Пользователь поручил Product-реализацию; обычные технические решения в этих границах не требуют повторного approval. Второй anchor, изменение защищаемого имущества или переписывание истории — STOP с конкретным новым контрактом.

## Global Constraints

1. UTF-8; чужой WIP сохранять. Код/тесты/скрипты пишет Sol, Astra не реализует. Один итоговый обзор Product после общей проверяемой реализации.
2. Не редактировать байты старых V1/V2 migrations/schema profiles/digests/receipts. EF относительно опубликованной базы только additive, без seed ресурсов/consent. Ещё не опубликованная V3 schema пересобирается по addendum §2.1 (13 protected tables вместо 14); её qualification повторяется, ранние V3 stand DB не считаются совместимыми автоматически. Полный sqlite_schema admission обновляется точными профилями, не широким wildcard.
3. Один anchor и одна DB transaction для protected effect. Legacy fallback после V3 при ошибке authority запрещён. Порядок: authority (A) → ordered colony locks (O) → storage barrier (S) → LiveStateLock, когда нужен → DB transaction; transaction начинается после всех необходимых locks. Запрещено acquiring authority под already-held Live; вложенные paths используют `CustodyEntry.Borrow()` / `UseHeldEntry(OutpostLease)` без повторного acquire или освобождения чужого lease. Существующие lock paths массово не менять. Никакой transaction вокруг network wait или вложенного BeginHeldAsync.
4. Game objects/main-thread; terminal после каждого actual tick, следующий tick заблокирован. Actor/side определяется auth, не payload. Result только от назначенного executor. Не переносить `tools`/RimBridge dependency в release.
5. Ни настоящих колонистов, ни personal workers, ни raid на home. Матчевые предметы/пешки не экспортируются. Обычные save/economy/custody paths заблокированы на battle mirror до восстановления дома.
6. Preset: 4×4, Move/Attack/Draft, 3000 hold/30000 ticks/20 min, AI 30 sec, coordinator grace 60 sec; экономика и campaign numbers из C не меняются ради тестов. Изолированный test clock явно помечать.
7. Протокол только additive, свободные field/oneof/ErrorCode numbers проверить перед назначением. RU/EN keyed strings, Wiki, CLI/REST/admin parity входят в задачу.
8. Gates OFF по умолчанию; не подделывать seal и не переносить старый PASS на изменённый build. Секреты и game binaries/snapshots вне Git. GUI только CUA Driver; browser NOT RUN честно сохраняется до доступного штатного прохода.
9. Перед разрешённым commit нужны зелёные соответствующие проверки и git-safe-commit. Commit messages ниже — кандидаты для будущего разрешённого шага, не команда коммитить. Push/merge/deploy не делать.

## Review Focus

- Сохранение V1/V2 истории, V3 activation, schema lineage/DDL bytes, downgrade refusal и общий pending/DB/external commit.
- Race capture/claim/disband/leadership/freeze, old-stock obligation и новый yield; no double materialization после lost ack/rollback/restore.
- Сохранение существующего A→ordered O→S→Live (если нужен)→DB; отсутствие инверсии Live→authority и повторного acquire во вложенном caller; borrowed entry/lease не освобождает locks владельца.
- Горячий transport только S→battle lock, без полного asset digest; financial final A/O/S→Live, если нужен→battle lock→DB. Readiness/lease/fence повторно проверены под S; terminal seal и backup cut связывают journal с единственным anchor. Все SQLite/file handles закрыты до release S.
- Реальная независимость executor, role/lease/boundary/session epoch, bounded inputs, idempotent view/command/final.
- Battle context до смены Game и после crash: home save/upload/receipt не получают battle map; нет вывоза match-local assets.
- Reconnect/full mirror, pause/terminal tick, initial/final evidence lifecycle, cold final replay и unknown-outcome abort.
- Bidirectional tile claims; auth/scopes/admin confirmation; честная qualification final source/build, RU/EN equivalence.
