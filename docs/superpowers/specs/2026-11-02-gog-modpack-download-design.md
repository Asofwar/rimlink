# Загрузка серверного модпака для GOG

Автор спеки: Astra. Реализация: основная сессия, GPT-6.1 Sol.
Дата: 2 ноября 2026 года. Статус: **черновик для утверждения**; реализация не начата.

## Цель и границы

Игрок GOG получает точные версии необходимых модов с выбранного сервера, подтверждает изменения, устанавливает пакет и один раз перезапускает игру для повторного входа. Запущенный Steam, SteamCMD и подписки Workshop не требуются.
Первая поставка — один неизменяемый серверный пакет и один интерфейс исправления ModpackDiff. Магазина модов, поиска зеркал, загрузки зависимостей из интернета и произвольных URL нет. Steam-путь остаётся отдельным существующим вариантом; WorkshopID служит справочной информацией и не обещает скачивание мода в GOG.

## Исходное состояние и зависимости

В текущем `ModpackActions` методы SubscribeMissing/PendingDownloads возвращают 0 без Steam; это не подтверждение наличия файлов. FixAndRestart сам по себе GOG-доставку не выполняет. Новый путь разрешает перезапуск только после проверки полного результата установки.
Используются существующие comparer, ModpackDiff/ModpackDiffView, CertificatePinStore, ModContent и JoinIntentStore; новые точные методы и номера протокола определяются последующим планом.
По уточнению пользователя AdminBypass — желаемое поведение: администратор вправе входить с отличающимся модпаком до и после создания мира. Его сохранение обязательно; зависимости от отмены обхода нет. Доказательство успешной установки — проверка файлов/порядка/settings и вход обычного игрока, а не один успешный admin login.
Аутентификация отдельна от доставки. Текущий production использует Steam login и `allowPassword=false`; эта фича не меняет их автоматически, не создаёт аккаунты и не предоставляет GOG-игроку Steam-личность. До скачивания UI показывает, поддерживает ли сервер доступный игроку способ входа; при Steam-only не обещает успешный GOG-вход после установки.

## Публикация пакета администратором

Администратор с существующими административными полномочиями явно публикует пакет для текущего списка обязательных модов. Раздавать можно только моды, на распространение которых у него есть разрешение; наличие WorkshopID или установленной копии само по себе разрешением не считается.
Пакет включает целые необходимые каталоги разрешённых модов с About, ресурсами, Defs/Patches/Assemblies и версионными подкаталогами. Игра, Core, DLC, пользовательские Config, сейвы, логи, серверные конфиги, учётные данные и ключи исключены. Источник — отдельно подготовленный набор каталогов модов, не архив всей игры/сервера. Неоднозначный или запрещённый состав отклоняется до публикации.
Доставляются все обязательные распространяемые моды и их обязательные зависимости; необязательные разрешённые моды автоматически не выбираются. Если обязательный мод нельзя распространять, публикация полного пакета отклоняется с его именем; частичный пакет не выдаётся за автоматическое исправление.
Манифест содержит packageId, имя, версию, FilesHash и обязательный SHA256 `mods[].contentHash`, совместимость игры, зависимости/конфликты, порядок, DLC, размеры, число файлов и безопасный ID каталога; для пакета — ID, ревизию, SHA256 архива и размер. JSON format1 ещё не опубликован: поле contentHash добавляется в него без новой версии; отсутствующий/некорректный hash отклоняется. Дубли нормализованного packageId запрещены.
Архив и манифест проверяются до атомарной смены указателя опубликованной версии. Изменение серверного списка модов делает прежний пакет непригодным для нового исправления; активная загрузка остаётся привязана к конкретному ID и не подменяет байты новой версией. Удалённая версия даёт явный отказ, а не другой архив под тем же ID.

## Доступ до login и доверие

Доставка имеет отдельный ограниченный bootstrap-доступ на том же HTTPS-сервере. Он не требует успешного игрового login с совпадающим модпаком и не создаёт игровую сессию. До выдачи манифеста проверяется приватный serverPassword, если он установлен; у сервера без пароля публичность именно опубликованного пакета осознанно подтверждается администратором при публикации.
Сначала выполняется существующая проверка TLS pin. Новый/изменившийся сертификат требует обычного явного решения пользователя; никакого автоматического доверия из манифеста. ServerPassword передаётся только после проверки pin, в защищённом теле запроса, не в URL, логах или файле намерения.
После проверки доступа выдаётся случайный краткоживущий download token: только чтение одного package ID, срок 15 минут. Он не даёт доступа к Config, административным API или игровому login. Клиент держит токен в памяти; для продолжения после истечения/перезапуска вновь получает доступ, при необходимости запрашивает пароль. Смена serverPassword или снятие публикации отзывает доступ и блокирует новые запросы/продолжение передачи.
Манифест не задаёт адрес загрузки. Клиент строит путь по фиксированному контракту своего ServerEndpoint и package ID; только тот же origin и pin, без редиректов, внешних хостов, file/UNC URL и адресов из игровых данных. Это также исключает SSRF при публикации: сервер принимает подготовленные файлы, не скачивает ссылки из манифеста.
TLS и хеши подтверждают источник и целостность, не безопасность кода мода. В подтверждении явно сказано, что моды могут содержать исполняемые сборки доверенного администратора; инсталлятор не запускает их, сторонние установщики или post-install команды.

## Один интерфейс исправления

В существующем окне ModpackDiff появляется вариант «Скачать пакет сервера» с режимом GOG. До подтверждения показываются сервер, package ID, список/версии, размер загрузки и распаковки, требуемое место, изменения порядка и точные действия с локальными копиями. Отдельно видны отсутствующие DLC и недоступный способ аутентификации.
Проверка до записи: совместимая игра, все необходимые DLC уже установлены, обязательные зависимости замкнуты, нет циклов и заявленных несовместимостей, серверный порядок согласован с зависимостями. Core/DLC берутся только из локальной игры и остаются в положенном порядке. Покупка/скачивание DLC и изменение прав доступа не выполняются.
Exact reuse требует совпадения packageId, версии, FilesHash **и ContentHash всех файлов**, включая About/Textures/звуки/локализации. Один FilesHash недостаточен: отличающаяся Textures чужой копии блокирует reuse без изменения её файлов. Extra отключаются только по правилам comparer, не удаляются. PackageId нормализуется как прежде; имена файлов для ContentHash регистрозависимы.
При нескольких локальных копиях одного packageId нельзя полагаться на порядок поиска игры. До установки выбрать одну проверенную копию; конфликтующие копии, которые ранее установил этот загрузчик, можно убрать из области сканирования в его собственный rollback-каталог. Неуправляемые чужие копии не перемещаются, не заменяются и не удаляются автоматически: конфликт блокирует установку и перечисляет пути для ручного разрешения. Это намеренное ограничение первой поставки.
Settings-часть ModpackDiff не исправляется архивом модов. Существующий механизм согласованных серверных настроек остаётся отдельным явным действием; доставка пакета не копирует пользовательский Config и не считает оставшийся Settings diff исправленным. Перезапуск разрешён только когда все категории diff имеют проверенный результат либо подготовленное штатным механизмом действие для следующего запуска.

## Проверка, staging и установка

Архив загружается в staging вне сканируемых каталогов на томе Mods. Сверяются размер/SHA256 архива, packageId/версия из About, прежний FilesHash и ContentHash каждого мода. ContentHash — SHA256 канонического представления относительных имён ВСЕХ файлов, упорядоченных case-sensitive ordinal, и SHA256 полных байтов каждого файла. Packer, ZIP-validator, дисковый metadata reader и installer независимо вычисляют его; hash из манифеста не принимается на веру. Gameplay FilesHash по-прежнему охватывает только Defs/Patches/Assemblies; его алгоритм и protobuf не меняются. SHA256 архива остаётся обязательным.
Распаковка не следует ссылкам и проверяет фактические размеры потоков. Запрещены абсолютные пути, выход через `..`, drive/UNC, ADS, зарезервированные имена Windows, symlink/hardlink/reparse points, шифрованные записи и коллизии нормализованных путей с учётом регистра. Проверка проводится относительно разрешённого staging-root до каждой записи; вложенные архивы автоматически не распаковываются.
Новые моды ставятся только в уникальные каталоги, принадлежащие загрузчику; владение фиксируется его локальным журналом, а не наличием packageId. Существующие неуправляемые каталоги не перезаписываются. Обновление управляемого мода сохраняет предыдущую версию вне области сканирования до завершения операции.
До изменения ModsConfig сохраняются точные байты/факт отсутствия. Журнал хранит package ID, пути/хеши, порядок, шаги и backup, без секретов. Пустые каталоги не влияют на ContentHash; отдельный локальный TreeHash учитывает их и файлы для защиты удаления/rollback. Проверка TreeHash перед удалением/восстановлением собственных результатов не заменяется ContentHash: внешнее изменение, включая пустой каталог, останавливает разрушительный шаг с сохранением обеих версий.
Замена каждого каталога и ModsConfig атомарна в пределах тома. Вся операция над несколькими каталогами не объявляется одной атомарной файловой командой: журнал обеспечивает завершение или откат при сбое, а новый ModsConfig публикуется последним, только после установки всех файлов. Обычный вход/повторная установка блокируются, пока незавершённая операция не восстановлена. Загруженные или заблокированные старые DLL не заменяются; при блокировке — безопасный отказ, без принудительного завершения игры.
После commit повторно проверяются локальные файлы и рассчитанный активный список штатным comparer. Старые управляемые версии и ModsConfig-backup сохраняются как минимум до первого успешного входа с новым составом; пользовательский оригинал не удаляется при уборке.

## Перезапуск, повторный вход и откат

Успешная установка создаёт одно join-intent для того же сервера и вызывает один перезапуск с согласия пользователя. Используется JoinIntentStore: намерение одноразовое, имеет существующий срок 15 минут и не хранит пароль. Файловая доставка не помещается в TransferOutbox и не изменяет его: незавершённые игровые операции остаются привязаны к прежним серверу/игроку и переигрываются только после обычного успешного login.
После запуска проверяются загруженные моды, версии, FilesHash/порядок и ContentHash их дисковых корней по манифесту; новый diff показывается без автоматического restart. ContentHash не расширяет серверный gameplay comparer/protobuf. Автовход — одна попытка обычного login, пароль при необходимости спрашивается заново. Steam-only/auth/network отказ не запускает restart-loop и не откатывает исправные файлы.
Незавершённая установка обнаруживается на следующем старте до нового join. Для возврата к прежнему составу восстанавливаются исходный ModsConfig и управляемые каталоги из журнала; созданные этой операцией каталоги убираются из области сканирования. Если пользователь успел изменить файлы, автоматический откат останавливается и сохраняет обе версии, предлагая точные пути восстановления. После загрузки модов откат применяется через следующий осознанный перезапуск, не горячей заменой сборок.
Ошибка запуска игры оставляет журнал и backup доступными для восстановления без успешного старта мода. В инструкции игрока описывается ручное восстановление ModsConfig из сохранённой копии и управляемых каталогов по журналу; внешнего привилегированного помощника в первой поставке нет.

## Resume, cancel, ошибки и пределы

Resume использует Range только для неизменного package ID/SHA256/размера и совпадающего ETag. Если сервер не поддерживает Range, изменился validator или локальный фрагмент повреждён, загрузка начинается заново после уведомления; окончательный SHA256 проверяется всегда. Запись прогресса не является согласием на другой пакет: новый manifest требует нового подтверждения.
Cancel до commit прекращает передачу и не меняет моды/ModsConfig; пользователь выбирает сохранить проверяемый фрагмент для resume либо удалить только staging этой операции. Cancel во время commit завершает безопасный шаг и запускает откат по журналу; не оставляет половину нового активного списка. Удалять чужие файлы или общие кеши запрещено.
При смене опубликованной ревизии перед commit клиент останавливается и показывает новый diff; не устанавливает незаметно другой пакет. Гонка смены после этой проверки ловится повторным сравнением при login. Таймаут, потеря связи, истечение токена, неверный пароль, недоверенный pin, hash mismatch, нехватка места/прав, блокировка файлов, неподдерживаемый DLC и конфликт копий имеют отдельные понятные сообщения и не вызывают перезапуск.

| Предел первой поставки | Значение |
|---|---|
| Одновременная операция клиента | 1; повторное нажатие продолжает её, не создаёт вторую |
| Манифест / число модов | 1 МиБ UTF-8 / 512 |
| Архив / распакованные данные | 2 ГиБ / 8 ГиБ суммарно |
| Записи / один файл | 100 000 / 512 МиБ |
| Сжатие / глубина | ≤100:1 для записи и всего пакета / ≤16 компонентов пути |
| Путь | Относительный ≤180 символов; итоговый путь ≤240, иначе отказ до записи |
| Место до старта | Размер архива + полный распакованный объём + объём backup + запас 512 МиБ |
| Bootstrap | 5 попыток в минуту на адрес, не более 64 одновременно активных download token |
| Передачи сервера | Не более 4 одновременно, один поток на token; превышение — временный отказ, без усечения |

Лимиты проверяются при публикации и независимо на клиенте; превышение запрещает пакет целиком. Сырые пароли/token и содержимое Config не попадают в диагностику. Политика bootstrap использует существующую нормализацию адреса и доверие к proxy; заголовок клиента сам не задаёт ключ ограничения.

## Приёмка и переход без потери данных

- GOG без запущенного Steam получает разрешённый пакет, проверяет его и входит после одного restart с точным составом; отсутствие файлов никогда не трактуется как ноль ожидающих успешных загрузок.
- Приватный манифест/архив недоступен без serverPassword; истёкший/отозванный token, чужой package ID, изменённый pin и внешний redirect дают отказ. Игровая аутентификация не обходится, Steam-only остаётся Steam-only.
- Проверяются missing/version/files/order/extra/settings, DLC, dependency cycle, duplicate packageId, точная локальная копия и конфликт чужой копии. Обычный игрок проходит comparer; AdminBypass сохраняет вход администратора с отличающимся модпаком, включая мир после настройки.
- При одинаковом FilesHash отличающиеся Textures/About/прочие файлы меняют ContentHash и исключают exact reuse чужой копии. Pack/ZIP/disk/installer дают одинаковый ContentHash независимо от порядка обхода; смена регистра имени влияет на него, пустые каталоги — нет, но меняют TreeHash и защищены от удаления/rollback. Отсутствующий contentHash отвергается; прежний FilesHash/protobuf сохраняется. SHA256 архива, traversal/links/ADS/collisions/bomb/size проверки обязательны.
- Разрыв/возобновление, смена manifest, cancel на каждой стадии, disk full, locked DLL, crash между перемещениями и записью ModsConfig не повреждают исходный состав. Проверить восстановление после перезапуска и ручное восстановление при невозможности запуска игры.
- Проверяются одноразовый join-intent, запрос недостающего пароля, отсутствие restart-loop, неизменность игровых outbox и пользовательских настроек. Аутентификационный отказ не стирает установленный корректный пакет.
- Для старого сервера без доставки — явная недоступность и ручная установка, без пустого FixAndRestart. Старые клиенты продолжают существующий путь; обязательной подписки Steam для нового GOG-пути нет.

Публикация первоначально отсутствует; миграция не архивирует существующую игру автоматически и не включает раздачу. Старые моды, ModsConfig, pin, join-intent и outbox сохраняются; журнал появляется только после явного подтверждения новой операции. Отключение раздачи прекращает новые загрузки, но не удаляет установленные моды и резервные копии игроков.
Приёмка здесь — требования, не отчёт о прогоне. Пользователь подтвердил отсутствие GOG-копии: настоящая GOG acceptance не выполнена и не заявляется; upcoming-версия общая с guilds — 0.8.0. ContentHash уточняет уже одобренную точную копию. В этой документальной правке код/тесты/protobuf/настройки не менялись и прогоны не запускались; единственный общий code review будет отдельно после игрового прогона.
