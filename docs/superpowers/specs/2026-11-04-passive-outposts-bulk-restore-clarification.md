# Passive outposts: bulk restore, fresh fence и original provenance

Дата: 4 ноября 2026 года. Подтверждённая developer runtime модель автора проектного уточнения: `gpt-6-astra`.

**Статус:** main принял bounded mechanical ruling как уточнение уже одобренного Task14, без нового игрового выбора. Это design/plan clarification для реализации основной Sol, **не code review/итоговое review и не заявление реализованности**. Сценарии ниже предложены, но этим уточнением не запускались. Capability остаётся OFF до dependencies и acceptance; единственное whole-branch review — после Task16.

Основа: [approved design §9.3–9.4](<2026-11-03-passive-outposts-design.md#L310-L326>), [Task14](<../plans/2026-11-03-passive-outposts.md#task-14-consistent-backup-и-recoverable-stopped-server-restore>), [lifecycle/rollback clarification](<2026-11-04-passive-outposts-lifecycle-clarification.md>), [ordinary-return clarification](<2026-11-04-passive-outposts-ordinary-return-clarification.md>). Исходный design, Task13 и остальные tasks не переписываются. Новые имена ниже — требуемые interfaces/states, не существующие API.

## 1. Уже утверждённые ограничения

- Backup — весь согласованный cut: main DB, saves, необходимые archives/retired-world source/parcel/snapshot proofs, manifests/hashes и settled stock/checkpoints. Anchor вне DataDir/backup/staging/extraction/replacement trees; backup хранит observed identity, **не копию authority DB/journal для восстановления**. Missing required bytes — invalid backup, не разрешение выкинуть ссылку.
- Lock order **A → sorted O → S → Live → T**; coherent cut удерживается до завершения DB/file capture. Offline restore использует эквивалентные исключительные process/file barriers и проверенную остановку сервера. Нельзя перейти на unprotected legacy entrypoint при feature history.
- Bulk restore выбирает весь cut, не merge с пост-cut колониями/имуществом. Новый boundary/head, quarantine старых локальных artifacts, controlled canonical download и следующее собственное fresh save обязательны. Не переносить имущество между worlds/generations.
- Original snapshot XML/links/receipts/captures/payloads и transition intent/digest неизменны. Exact world/owner/generation/write-epoch/boundary/id/raw hash — разные обязательные части proof. Permanent ordinary negative fences не отменяются; pending client intent не становится новым разрешением от login.
- External RestoreInProgress появляется до replacements. Старый пригодный набор сохраняется до проверки нового; multi-file rename не считается atomic. Неоднозначность — maintenance/manual, не guessed replay/compensation. Active restore gap не производит resources; archived outposts остаются paused. Принятый [SQLite/OS contract](<2026-11-03-passive-outposts-design.md#L284-L296>) не расширяется обещанием power-loss proof.

## 2. Technical clarification: data chain и external fence

**C** — exact head/digest проверенного selected backup cut; **E** — фактически наблюдённый current external committed tuple; **R** — новый `BulkRestore` transition/head; **Bnew** — fresh restore boundary. Это две отдельные связи:

- Main DB: **неизменный backup prefix Genesis…C → R**. OldHead/Predecessor у R относятся к C; R.Intent отдельно содержит E как `previous-external witness`, archive/manifest digest, source installation/world/boundary/head, mode/operator confirmation и target installation/world/Bnew, owner scopes и protected projection/authorization maps. Effects связывает реальные restored domain rows.
- External authority: **E → RestoreInProgress(restoreId, selected cut/digests, target fence, journal commitment) → R**. Это специальная explicit restore publication, не ordinary Pending(E→R) с вымышленным predecessor. Не объявлять C предком E без доказательства. Проверяется согласованность exact marker/journal/final main R, а не одно совпадение UUID.
- Typed chain replay разрешает этот seam только для `BulkRestore`; ordinary Begin/transition scope checks остаются строгими. [Текущий Open](<../../../src/Rimlink.Server/Application/Outposts/OutpostAuthority.cs#L307-L358>) с WorldBind-веткой нельзя расширить blanket boundary/installation bypass. [Task13 Kind=Restore](<../../../src/Rimlink.Server/Application/Outposts/OutpostLifecycleRestore.cs#L15-L34>) — unarchive одной колонии, не bulk restore.
- Existing-installation restore сохраняет InstallationId; world/generation/player write-epoch берутся из selected cut, не из пост-cut E. Bnew — новый fence; искусственный world/generation rollover или e→e+1 только ради bulk restore не требуется. Import/recovery с новой installation имеет явный typed source→target seam; старый Initialize/prefix не переписывается и новая Genesis не выдумывается.
- Post-cut набор E не примешивается к игровому domain C. Он сохраняется отдельно для verified backout до completion; если final evidence ссылается на его объекты, они остаются retained и после completion. Весь original graph selected cut, включая все retired worlds и существующую nested restore/rollback provenance, проверяется по реальным bytes. Ненужный позднейший cleanup не часть этой процедуры.
- Исходные transition/snapshot rows остаются original. Main current authority и operational projections могут получить Bnew только через digest-covered before→after map R с exact source row/frontier/proof. Same owner/location/custody/assignment сохраняются; продвижение current frontier к R — typed same-state restore, не transfer. Старые lifecycle intents неизменны: новая доказанная BulkRestore projection supersedes только их current constraints, а исторические связи продолжают проверяться по исходным scopes. Whole-domain digest без semantic current-projection validation недостаточен.
- Валидный selected cut с Completed NoActiveWorld остаётся NoActiveWorld, а не фабрикует World: после coherent completion разрешён только прежний admin successor path; gameplay по-прежнему закрыт. Unfinished destructive lifecycle не превращается в Completed из-за bulk copy; он остаётся fenced до своей доказанной recovery.

## 3. Technical clarification: explicit operator modes

| Mode | Обязательный источник и результат | Что запрещено |
|---|---|---|
| ExistingInstallationRestore | Действительный E, exact выбранный archive/manifest digest и source installation; та же installation, fresh Bnew | Копировать anchor из archive; использовать DB UUID вместо actual E; называть повреждённый old set пригодным backout |
| ImportNewHost | Позитивно проверенный новый destination, отдельно provisioned fresh anchor store, explicit import; новая installation+Bnew, original source identity остаётся provenance | Initialize поверх imported history; принимать «файла нет» за empty installation; autoimport при startup |
| LostAnchorRecovery | History + missing/unusable anchor: normal startup/Initialize отказывают. Отдельный explicit recovery/import из полного verified cut в freshly provisioned fence с новой installation+Bnew; previous-external witness явно unknown/unavailable | Угадывать E по main DB; воссоздавать потерянную authority identity или копировать старый journal; принимать неизвестный storage profile |

`RestoreRequest` связывает restore-id, canonical archive/data/anchor paths, inspected archive+manifest digests, mode, expected destination/external observation и operator confirmation с этим exact выбором. Execute перепроверяет их под barriers, а не доверяет прежнему Inspect. Для нового/потерянного anchor сохраняется доказанная причина отсутствия E, не fake Genesis/empty-history assertion. Наличие pending/restore с другим ID или необъяснимой identity — refusal. Явная fenced recovery может использовать valid E при повреждённом current main, но backout тогда допускается только к действительно проверенному пригодному набору.

Legacy/no-feature bootstrap остаётся отдельным прежним путём лишь после доказанного отсутствия требующейся истории. Новые modes не расширяют права: только authorized offline operator, без force. Реальные archive/mode/Resume-vs-backout выбирает оператор **при execution**; для synthetic test fixtures этот реальный пользовательский выбор не нужен. Production/user backups это уточнение не открывает и не изменяет.

## 4. Technical clarification: controlled download и fresh acceptance

- Ввести отдельный additive `OutpostRestoreBridge` в [outposts.proto](<../../../src/Rimlink.Protocol/Protos/outposts.proto>), optional restore bridge в [SaveHeader](<../../../src/Rimlink.Protocol/Protos/saves.proto>) и `OutpostSaveMetadata` с новыми tags; существующие поля не переиспользовать. Не новый игровой RPC. Минимальные поля: committed restore operation/transition ID+digest, selected cut/manifest commitment, exact canonical original snapshot id/raw SHA256/original scope, source authorized scope at cut, target current scope, compatible local-frontier digest и bounded exact mutable-own-registry before→after map.
- Header/file/current scope/bridge выбираются одной locked canonical cut по **IsCurrent**, не highest Number. Bridge выдаётся только из committed stored restore evidence. Client echo — структура/provenance, не authority; на upload сервер повторно проверяет original bytes, journal, target binding/owner/gen/epoch, map и lineage. Подмена source/target/digest либо недоступный required proof — refusal, не null/legacy fallback.
- Сначала проверить authenticated download/header и реальные canonical bytes/id/hash/frontier, затем на **main thread** согласованно обновить только mutable outer scope и перечисленные живые собственные registry bindings. UUID/assignment/reference/ownership/location/tombstone не менять, новые custody IDs не генерировать; foreign historical/mirror observations не пересаживать. Original file/XML, pending/outbox и historical registry observations не редактируются. Partial/ambiguous application блокирует writes.
- Затем нужен **новый actual captured snapshot с новым id/hash/Bnew**, accepted до новых mutating proofs/delivery этого клиента. First acceptance доказывает соответствие approved map/frontier и сохранность carried originals; замена scope в старом XML/queued upload не fresh capture. Старые pending/local proofs остаются quarantined; login ничего не reauthorizes. После first fresh acceptance bridge остаётся проверяемой provenance, не повторным разрешением менять registry; последующие обычные transitions могут расширять frontier по прежнему контракту.
- [Rollback bridge](<../../../src/Rimlink.Client.Core/Outposts/OutpostRollbackBridgeChecks.cs#L10-L36>) остаётся same-world/owner/gen/boundary и e→e+1. Restore-after-rollback/repeated restore/rollback-after-restore проверяют **каждую typed связь** до exact original canonical metadata. Старый bridge.CurrentScope/digest не переписывается новым B. Новый active root bridge ссылается на предыдущий original proof; прежний bridge сохраняется там как immutable source provenance, а не остаётся конфликтующей active authorization нового scope. Bounded chain traversal сохраняет все необходимые references; unsupported/cyclic/oversized/неполная цепь — refusal, не truncation в «достаточный» proof.
- Historical capture/receipt branch только для **доказанно accepted terminal** original evidence и exact provenance path. Не удалять scope equality повсюду и не объявлять любой old boundary допустимым. Parser проверяет bounded structural связь; сервер доказывает accepted authority по journal/real bytes. Old Prepared/Started/Ready не переавторизуются, completed ordinary capture не становится новым outgoing, negative fence не отменяется.
- **LegacySnapshot:** по classifier [lifecycle §4.1](<2026-11-04-passive-outposts-lifecycle-clarification.md#41-legacysnapshot-и-protectedsnapshot>) нет required protected provenance за все relevant epochs/dependencies — controlled download обычных exact legacy bytes/header и fresh save сохраняют0.8.1 поведение; outpost registry bridge null после проверки, без fabricated metadata/OutpostSnapshotLink/embedded original scope. Global history другого owner не делает этот snapshot protected. **ProtectedSnapshot:** exact original link/graph/restore bridge обязательны; missing/malformed/unknown не переводятся в legacy.

## 5. Technical clarification: original parcel и authorization

- Для доказанного committed pending parcel selected cut создать одну authorization на `(Bnew, original parcelId)`: original immutable payload bytes/digest, original source link/canonical proof, restored recipient/world/generation, target current scope и restore R. [Существующая authorization entity](<../../../src/Rimlink.Server/Storage/Entities/OutpostRecords.cs#L170-L178>) — связующее звено, но без typed joined evidence её bare fields недостаточно. Новая main restore record/maps и authorization rows покрываются domain digest; старые payload.Scope/receipt/transition не обновляются.
- После first fresh accepted snapshot новый текущий delivery attempt/request связывается с **той же** original parcel ID, authorization и current canonical proof. Это новый доказанный current attempt, не replay old Begin/Commit/outbox. Payload не клонируется/не пересериализуется с Bnew. Server и client проверяют exact source→target authorization вместо обычного payload/request same-scope только в этой квалифицированной ветке; обычные [server checks](<../../../src/Rimlink.Server/Application/Outposts/OutpostParcels.cs#L66-L84>) и [client checks](<../../../src/Rimlink.Client.Core/Outposts/OutpostDeliveryEvidence.cs#L32-L49>) остаются строгими. Перед materialization проверяются actual contents/digest, recipient/custody, fresh proof, current branch/session и single-use состояние.
- Если accepted original receipt уже содержится в выбранном canonical, только **ACK-only** по original attempt/receipt/payload/canonical proof и restore provenance: no spawn/credit/re-finalization/новая копия parcel. Если canonical более ранний, а cut содержит более поздний accepted receipt, нельзя молча считать его pending: требуется доказанный совместимый canonical/provenance либо affected path fenced/manual.
- Prepared/Started/unresolved не массово обнуляются и не становятся Accepted от restore. Автоматическое разрешение возможно только при единственном исходе, доказанном сохранёнными transitions и canonical bytes; иначе manual RecoveryRequired. Нельзя объявить полный readiness при unresolved affected path, удалить его evidence или обещать компенсационные копии. Новые authorization links при repeated restore ссылаются на исходный parcel/payload и всю требуемую предыдущую provenance, а не обнуляют её.

## 6. Technical clarification: durable phases, Resume и backout

Versioned `RestoreJournal` живёт вне replacement trees и связан commitment с external marker. Он хранит immutable request/mode/source C/observed E/target Bnew, canonical paths, old/new inventories, exact file hashes/locators, per-component planned/completed facts, main head/effects и outcome. Его unbounded contents не запихиваются в bounded anchor record; неподтверждённый sidecar не authority. Existing RestoreInProgress и ordinary Pending одновременно не допустимы: используется explicit restore state machine, не ordinary Begin под ослабленным Ready.

| Phase | Проверяемый смысл / следующий разрешённый шаг |
|---|---|
| Inspect | Read-only archive/destination/identity/limits/proofs; никакого переключения или provisioning |
| Fenced | Под locks заново проверены digest/mode/destination; durable external RestoreInProgress+связанный journal до replacements |
| StagedVerified | Bounded safe extraction; вся DB/graph/full/delta/base/archive/blob evidence verified, including retired worlds и original captures/ordinary fences |
| OldSetRetained | Зафиксированы реальные старые bytes/locators и проверенная пригодность backout; corrupted old set не маркируется usable |
| Switching | Каждый DB/saves/archive move/copy имеет planned fact до effect и independently verified completion; mixed live set не обслуживается |
| InstalledVerified | Установленные paths/bytes/schema/graph совпадают с staged manifest; future current projection/maps/authorizations однозначны |
| MainCommitted | Одной main transaction применены typed restore maps/authorization links, R/head/domain digest и completion evidence; external marker всё ещё закрывает обслуживание |
| Completed | Exact installed set и main R перепроверены; external authority публикует target tuple/R и завершение, после чего доступны controlled read/download, но не stale client writes |

- Source archive, required retained evidence и external fence не удаляются/не подменяются cleanup. Прерывание любой незавершённой фазы оставляет maintenance, не обычный startup repair/upload/delivery/replay/production. Process-kill tests проверяют эту state machine, не произвольное hardware power-loss свойство.
- `Resume(expectedRestoreId)` — explicit completion существующей операции после проверки exact journal/request digest/actual files/head; другой ID, changed archive/target/phase или ambiguity — refusal/maintenance. Он не запускает destructive business actions повторно и не выделяет второй B/parcel/receipt. Already Completed возвращает проверенный тот же outcome.
- **Backout — отдельный explicit confirmed action**, не автоматический fallback Resume. До external publication R он разрешён только к проверенному сохранённому old set/E под тем же marker с journalled обратными шагами и полной проверкой результата. Для new-host import возможен лишь доказанный исходный empty destination; неизвестный/повреждённый old set не пригоден. После публикации R вернуть E/старый boundary нельзя: возврат старого набора требует новой explicit restore procedure с ещё одной fresh boundary.
- Cut stock/fraction сохраняются, backup→accepted completion/resume gap даёт **0 production**. Active outposts suspended до accepted resume checkpoint; archived paused. Если crash растянул restore после раннего MainCommitted, explicit Resume закрепляет новый защищённый completion/checkpoint step без yield и без переписывания immutable R; внешний marker связывает точный финальный descendant head. Это продолжение того же restore-id/B, не второй restore/повторная authorization. После доказанного completion обычные restarts снова считают обычный downtime, а не повторяют restore rebase.
- Partial validity не Ready: normal startup отличает unfinished restore, completed coherent restore, Completed NoActiveWorld и непригодный set. Restore completion само не включает feature capability и не отменяет оставшиеся readiness/acceptance gates.

## 7. Interfaces для Task14, не готовая реализация

- `OutpostRestoreProcedure.InspectAsync(string archivePath, string dataDir, string anchorDir, CancellationToken ct) → Task<RestoreInspection>`; `ExecuteAsync(RestoreRequest request, CancellationToken ct) → Task<RestoreResult>`; `ResumeAsync(string dataDir, string anchorDir, string expectedRestoreId, CancellationToken ct) → Task<RestoreResult>` остаются entrypoints. Resume завершает, не выбирает backout. Добавить `BackoutAsync(RestoreBackoutRequest request, CancellationToken ct) → Task<RestoreResult>`: exact restore-id/paths, inspected journal commitment/expected phase и explicit operator confirmation; после publication отказ. Request/inspection/result/mode/journal types co-located в planned `src/Rimlink.Server/Backup/OutpostRestoreJournal.cs`; result различает Completed/BackedOut/Maintenance/Refused и exact restore/head identity, не bool «всё хорошо».
- Planned `src/Rimlink.Server/Application/Outposts/OutpostRestoreEvidence.cs`: `ValidateStoredAsync(CancellationToken ct, OutpostTransition? staged = null) → Task`; `GetDownloadBridgeHeldAsync(OutpostLease lease, long playerId, SaveVersion target, CancellationToken ct) → Task<OutpostRestoreBridge?>`; `ValidateProvenanceAsync(OutpostSaveMetadata metadata, CancellationToken ct) → Task<OutpostSaveMetadata?>`. Read-only под fence; staged R передаётся явно; null только proven no-bridge/Legacy, required evidence missing — refusal. Проверять exact chain/phase/map/current projections/real original bytes, не generic lifecycle whitelist. Resolver Task13 остаётся источником retired locators.
- Planned `src/Rimlink.Client.Core/Outposts/OutpostRestoreBridgeChecks.cs`: `Validate(OutpostRestoreBridge bridge, OutpostSnapshotProof downloaded, OutpostScopeMessage current, IReadOnlyList<PawnRegistryEnvelope> registry) → RestoreBridgeDecision`. Pure bounded AllowedForFreshCapture+exact update plan либо RecoveryRequired; same-owner/gen/world selected-cut mapping, только fresh boundary transition. Download dispatcher выбирает ровно один active bridge kind; rollback checker не ослабляется. Применение плана — существующий game main-thread path.
- Backup manifest содержит version, cut/current authority identity, exact snapshots и file inventory/hash/size/reference closure, original archive manifests, protected source/parcel/negative-fence graph, geographic manifest и checkpoints. Один защищённый orchestration path используется CLI/manual/scheduler; existing legacy BackupArchive entrypoints сохраняются только для proven no-history, otherwise требуют explicit authority context/refuse. Root spec не расширяется произвольным merge/force/admin capability.

## 9. Принятое уточнение: fresh fence без вымышленного E

Дополнение main-принятого mechanical ruling к §2–3/6; исходные §1–8 сохраняются. Это представление уже выбранных ImportNewHost/LostAnchorRecovery, не новая игровая политика, реализация или проверенный test result.

- **Additive anchor envelope:** v1 bytes/семантика и путь Known-E остаются прежними. Внутренний tagged format v2 добавляет FreshFence со состояниями RestoreInProgress и BackedOutEmpty: fresh fence ID F, restore ID, mode, target installation/world/Bnew, immutable intent digest и явный PreviousWitnessKind. Committed и ordinary Pending в этом варианте отсутствуют; не подставлять Genesis, C, Guid.Empty или случайный head. Сохраняются UUID/hash/checksum validation и предел 4096 bytes; подробные observations/inventories — в digest-covered intent. Неизвестный version/tag/combination отвергается, nullable Committed не ослабляет обычный v1.
- **Два разных наблюдения:** DestinationFenceObservation описывает реально проверенный target anchor store; PreviousAuthorityWitness — Known E, AbsentQualifiedEmpty для import либо Unavailable с причиной/наблюдением прежнего anchor для lost recovery. Здоровая новая пустая authority DB не превращает неизвестную старую authority/history в empty. Lost recovery использует отдельно provisioned healthy target fence, не пишет в повреждённый старый anchor; его old artifacts не становятся usable E.
- **Provision и привязка F:** существующий Provision создаёт проверенную физическую DB с NULL Record, не committed authority и не persisted logical identity. Под lifetime barriers Execute повторно проверяет confirmed selection, storage profile и qualified NULL store; durable immutable intent предшествует marker, а первая durable FreshRestoreInProgress запись с readback закрепляет F/id/intent/target. Replacements до этого запрещены. NULL/schema/path сами по себе не доказывают same fence; Resume требует exact сохранённый F и не вызывает Provision/не воссоздаёт missing, NULL, corrupted или чужой marker из journal. Подготовительный intent без marker ещё не Fenced: требуется заново подтверждённый preflight, не имитация same-fence Resume.
- **Positive empty import:** полный bounded inventory под exclusion доказывает отсутствие main DB и всех sidecars, saves/archive/retired proof bytes и других state artifacts. Допустим только exact allowlist инфраструктурных lock/control files и пустых известных directories; lock-файлы не удалять. Reparse/symlink, необъяснимые entries, ошибки/omissions или исчерпание bounds — refusal, не empty. Target anchor отдельно проходит schema/backend/journal validation, Record NULL, без чужого pending/restore/необъяснимого restore journal. Paths, inventory/allowlist и qualification входят в confirmed selection/intent и перепроверяются перед fence; флагов DirectoryExists/DatabaseExists/ProvisionedEmpty недостаточно. Inspect ничего не provision-ит.
- **Source/target seam:** main остаётся original Genesis…C→R, OldHead/Predecessor R относятся к C. R.Intent связывает exact source cut, target installation/Bnew, F/id/intent commitment и typed PreviousWitness. External fresh path: qualified uncommitted store→FreshRestoreInProgress(F)→genuine Committed(target,R), не E→R с придуманным E. Перед publication проверяются marker/journal/selection, C prefix, exact R/maps и actual bytes; F остаётся доказуемым в immutable R intent/journal. Fresh-envelope format не переписывает historical main row/transition format.
- **Fail closed:** Open распознаёт fresh variant до обращения к Committed и не возвращает Ready; IsPhysicallyUninitialized означает только настоящий NULL. Initialize отклоняет любой непустой envelope, включая BackedOutEmpty, и любую требующуюся history. Ordinary Begin не получает исключения; invalid/missing marker не становится no-history/legacy fallback.
- **Typed backout target:** VerifiedCommittedSet(E), VerifiedEmptyDestination(qualificationDigest) либо Unavailable(reason), а не bool, смешивающий пустоту с пригодным E. Import до actual external publication R может backout только к frozen VerifiedEmptyDestination под matching F marker и отдельным confirmed action. Обратные planned facts записываются до effects; удаляются лишь доказанно созданные данной операцией paths/bytes. Необъяснимые изменения — maintenance, не delete; lock/control files и external evidence сохраняются. После полной повторной empty verification journal=BackedOut и fresh envelope=BackedOutEmpty с прежними F/id/intent, без Committed. Не обнулять Record/не удалять anchor/не называть результат E или Ready. Это terminal aborted import, не разрешение Resume старой операции; следующий import требует нового explicit selection.
- **Lost/late backout:** unknown/unusable old set при LostAnchorRecovery не reusable E даже после копирования bytes; verified Backout к нему запрещён, состояние остаётся fenced/manual. После фактической publication R backout запрещён независимо от отставшей journal phase: только новая explicit restore с fresh boundary. Эти уточнения не включают capability, не отменяют G6/Task16 и не заявляют выполненных tests/build.

## 10. Принятое уточнение: bounded nested Restore↔Rollback provenance

Main принял этот ruling как механическое уточнение §4, не новую игровую политику и не code/final review. Это additive contract для реализации Sol; перечисленные проверки этим дополнением НЕ запускались. §1–9 и прежние v1 contracts не переопределяются.

### 10.1. Actual evidence и authorized view — разные типы

- **ActualSnapshotSource** содержит exact OutpostSnapshotProof реально существующего файла: original snapshotId/raw SHA256/world/owner/generation/epoch/boundary. Original XML, links, embedded bridges, receipts/captures и их digests остаются неизменными. Нельзя сохранить тот же id/hash, подменить proof.Scope на новый boundary и назвать это actual snapshot.
- **AuthorizedSnapshotView** — отдельный semantic type, НЕ OutpostSnapshotProof: ссылка на actual source, exact committed predecessor authorization (kind, operationId, transitionId/digest), effective authorized scope, local-frontier commitment и exact live-own registry projection/map. У view нет собственных raw hash/snapshotId: ссылка на physical source не утверждает существование нового файла. View получается только из проверенного typed provenance path, не из login/echo, и не принимается existing mutating-proof endpoints вместо fresh actual proof.
- SourceProvenance — discriminated ActualSnapshotSource или AuthorizedSnapshotView с bounded typed source/authorization references. Каждая ссылка связывает immutable identity/digest и исходный контекст; source graph не содержит произвольных вложенных копий XML. Старые original files доступны через retained exact locators, включая retired-world/parcel/source/negative-fence evidence.

### 10.2. Минимальный additive wire contract и один active root

- Существующие metadata rollback_bridge (tag9) и SaveHeader outpost_rollback_bridge (tag17) сохраняют v1 поля/семантику. В [outposts.proto](<../../../src/Rimlink.Protocol/Protos/outposts.proto>) добавить approved OutpostRestoreBridge и отдельный OutpostRollbackFromViewBridge; каждый optional новым tag в [SaveHeader](<../../../src/Rimlink.Protocol/Protos/saves.proto>) и OutpostSaveMetadata. Existing tags не переиспользовать. Общая SourceProvenance обслуживает оба новых типа; rollback-from-view нужен, когда physical original scope отличается от authorized source view. Это не ослабленная новая трактовка прежнего CanonicalSnapshot/SourceScope.
- Root связывает exact actual canonical proof, source ref/path commitment, свой committed operation/transition ID+digest, target scope, frontier и bounded exact registry map; Restore дополнительно связывает selected cut/manifest commitment. Server выбирает root из latest applicable committed lifecycle seam для одного locked IsCurrent/header/file/current-scope cut, не по приоритету заполненного поля и не по highest save number.
- В DOWNLOAD HEADER активен ровно один из rollback-v1, restore, rollback-from-view. Более одного — refusal; отсутствие допустимо только после verified no-rebase/Legacy classification. Bridge внутри скачанного ORIGINAL XML является historical source provenance этого snapshot, не вторым active header grant. Его CurrentScope/digest не переписывается текущим boundary.
- В новой fresh capture metadata echo содержит ровно выбранный новый root, не одновременно скопированный старый root в другом active top-level field. Прежний root остаётся в immutable source, на который ведёт provenance. После accepted fresh save echo — historical provenance, не повторное разрешение rebase; обычный download этого actual current-scope файла не требует active header bridge, если отсутствует новый lifecycle seam. Проверка сохранённой provenance при этом не отключается.

### 10.3. Typed edges без synthetic proof и обхода rollback fence

- RestoreStep сохраняет selected-cut world/owner/generation и source authorized epoch; переводит только на доказанный fresh boundary и approved live-own bindings. RollbackStep сохраняет world/owner/generation/BOUNDARY между source-view и target и требует epoch advance. Journal отдельно доказывает current e→e+1 и effective target epoch<=e: это не target.epoch+1.
- Для ActualSnapshotSource без view применяется существующий [OutpostRollbackBridgeChecks](<../../../src/Rimlink.Client.Core/Outposts/OutpostRollbackBridgeChecks.cs>) без ослабления downloaded==CanonicalSnapshot, proof.Scope==SourceScope и same-boundary epoch-advance. Для AuthorizedSnapshotView нужен отдельный checker с теми же namespace/epoch invariants и обязательным доказательством view. Не передавать ему relabelled OutpostSnapshotProof, не расширять old SameNamespace/equality на cross-boundary и не обходить live scope checks.
- Registry plan проверяет exact before→after каждого шага и композируется до одного main-thread применения. Меняются только разрешённые mutable scope bindings живых собственных entries; UUID/assignment/reference/owner/location/tombstone/foreign mirrors не меняются, custody IDs не генерируются. Partial/ambiguous application блокирует writes.
- Пример без промежуточной fresh capture: actual S0[B0,e7]→RestoreView[B1,e7]→RollbackView[B1,e8] при неизменном S0 использует active RollbackFromView, НЕ proof(S0,B1). S0→RollbackView[B0,e8]→RestoreView[B1,e8] использует active Restore. S0→Restore B1→Restore B2 использует последнюю Restore authorization при неизменных старых bridge objects.
- Если уже существует actual fresh S1[B1,e8], rollback S1→e9 использует v1 actual proof S1; прежний restore bridge остаётся historical provenance S1. Canonical source — реально скачиваемый файл S1, не искусственно flattened самый старый S0. Nested historical source graph всё равно проверяется, но не объявляет старые grants активными заново.

### 10.4. Exact resolver, технические bounds и fresh acceptance

- Server resolver проверяет actual original bytes/id/hash/scope/link/locator и committed intents/transitions каждого соответствующего source cut, exact maps/frontier и accepted terminal receipts/captures. Исторические связи проверяются в их original context; current World/owner/gen/epoch/boundary применяются к live root отдельно. Нужен typed validated source graph, не один loose original metadata и не правило «любой scope<=source разрешён». Client проверяет actual downloaded bytes и structural graph из authenticated header; echo не authority, server повторно проверяет stored graph на upload. Parser получает отдельные bounded branches для новых типов; старые v1 same-boundary checks не расслабляются глобально.
- **Новые технические limits только SourceProvenance graph/maps:** max authorization depth16, max total distinct source/authorization nodes256, aggregate projected-map entries10000. Для нового encoded metadata/header graph — общий budget4MiB; actual ancestor XML не вкладываются внутрь, а разрешаются по references и существующему per-save size budget. Старые metadata.Registry/Receipts/Frontier сохраняют прежние v1 PER-COLLECTION limits; новый aggregate10000 не суммирует эти старые collections и не меняет валидность original v1 metadata. Flat typed reference table не наращивает protobuf recursion с каждым ancestor.
- Traversal bounded, memoized, с visited identities/digests и проверкой backward source edges. Cycle, duplicate-conflict, unknown kind, несоответствие selected cut, oversized graph или missing required bytes — refusal. Не обрезать хвост, не удалять required original references ради лимита, не доверять одному последнему UUID и не возвращать Legacy/null при повреждённом protected graph. Legacy определяется отдельным полным relevant namespace/all-epochs/dependency classifier, а не отсутствием удобного bridge.
- Authenticated header+actual bytes+proved path разрешают только mutable state plan, затем обязательны НОВАЯ actual capture с новым id/hash/current scope и server acceptance ДО новых mutations/delivery. Authorized view не заменяет fresh save и не меняет original XML/queued upload. Old pending/outbox/Prepared/Started/Ready не переавторизуются; login не даёт перехода.
- Carried originals допускаются только при exact membership в доказанно accepted terminal source graph; исторические receipts/captures — ACK/history-only. Никаких повторных spawn/credit/ownership transfer или отмены permanent ordinary negative fences. Прежние local frontier/barrier checks сохраняются для каждого разрешённого lifecycle перехода.

### 10.5. Минимальные предложенные проверки — НЕ запускались

- Nested_restore_then_rollback_before_fresh_uses_view: S0 original scope/id/hash/XML неизменны; только typed view даёт B1→B1 epoch advance, view не принимается как mutation proof.
- Nested_rollback_then_restore_and_repeated_restore_preserve_sources; Nested_after_actual_fresh_uses_immediate_snapshot: все три комбинации до/после actual fresh S1, последняя применимая active authorization, original sources и carried receipts неизменны, canonical S1 не flattened в S0.
- Nested_multiple_active_header_bridges_refused; Rollback_v1_rejects_relabelled_synthetic_proof: отсутствие priority fallback, v1 same-boundary/proof equality и старые per-collection limits не меняются; historical bridge original XML не ошибочно считается вторым active header grant.
- Nested_tampered_source_scope_map_digest_or_cut_refused; Nested_cycles_conflicts_unknown_and_bounds_refused: missing actual source bytes, wrong owner/gen/boundary/epoch, provenance outside cut, cycles/duplicate conflicts; depth16/nodes256/new map10000/new graph4MiB на границе и за ней, без truncation/Legacy fallback.
- Nested_requires_actual_fresh_acceptance; Nested_old_pending_stays_quarantined_and_receipts_ack_only: login/echo/view/rewritten queued save не заменяют fresh capture, stale pending не воспроизводится; accepted historical receipt не создаёт повторный pawn/parcel/credit и не отменяет negative fence.

Это авторское дополнение не меняет plan, реализацию, capability/readiness OFF или G6/Task16 acceptance; не разрешает automatic destructive replay и не объявляет проверки выполненными.

## 11. Принятое уточнение: previous anchor observation и terminal fresh fence

Main принял mechanical ruling §9: текущий LostAnchorRecovery Execute допускает только KnownLocation с actual admissible unavailable observation. Это bounded clarification, не новая operator/game policy, реализация или результат tests; §1–10 сохраняются.

- **Typed reference:** Inspect принимает отдельный PreviousAnchorReference: KnownLocation(canonical previous anchor path) либо OperatorDeclaredUnknown(bounded declaration/reason). Выбранное оператором прежнее location и происхождение выбора сохраняются; путь не угадывается из backup, main DB или нового target. Для ExistingInstallationRestore остаётся прежний Known-E путь, для ImportNewHost — NotApplicableNewHost с positive-empty qualification, не вымышленное наблюдение старой installation.
- **Typed observation:** PreviousAnchorObservation отделён от DestinationFenceObservation: reference/path/origin, outcome/reason, доступный digest с exact subject/coverage прочитанных envelope/file/sidecar bytes. Недоступный digest имеет явную причину, не нулевой hash. Различать ObservedUnavailable, ObservedCommitted, ObservedPendingOrRestore, Inconclusive/Unsupported и UnobservedOperatorDeclaration. Missing по известному пути требует actual not-found, не обобщённого Exists=false/AccessDenied. Прежний healthy NULL при history — observed uninitialized/unusable, НЕ AbsentQualifiedEmpty; healthy новый NULL не доказывает отсутствие старого E.
- **Admission без новой policy:** omitted reference/observation и OperatorDeclaredUnknown дают explicit refusal, даже после confirmation. Существующая проверенная actor/action identity может подтвердить происхождение декларации, но не факт отсутствия authority; actor string/selection digest не аутентификация. Observed healthy committed требует нового выбора/подтверждения надлежащего existing mode, не auto-switch. Pending/restore/BackedOutEmpty, unsafe path/reparse, unsupported profile, limits или inconclusive/unstable observation не становятся Lost admission/force. Разрешение Execute только по unknown declaration потребовало бы отдельного operator-policy решения; здесь его нет.
- **Frozen request/selection/intent:** exact confirmation покрывает ОБА наблюдения с provenance/path/typed facts/digest/coverage, mode, source cut, target и storage profile. Freeze отделяет mutable buffers/collections до await; immutable intent сохраняет тот же payload либо включённую frozen selection с commitment. PreviousWitness определяется валидированными данными, не Mode. FreshFence хранит bounded kind и intent digest; детали остаются в digest-covered intent. Missing старое поле нельзя default-ить в ObservedUnavailable.
- **Read-only прежнего location:** observer не Provision/Initialize/recovery, не создаёт старые lock/journal files, не пишет в прежний anchor и не обходит access refusal. Доступные raw observations не используются как usable E/backout. Известный missing/corrupt/unreadable источник явно отличается от ненаблюдавшегося unknown; сохраняются прежние safety/profile/maintenance ограничения.
- **Двойной recheck до marker:** под существующим offline exclusion и lifetime target/data/storage barriers повторить exact destination И previous observation перед созданием immutable intent; после его durable записи повторить read-only проверку обоих непосредственно перед первым marker attempt. Сравниваются typed facts, canonical paths и доступные digest/coverage, не нестабильный exception text/timestamp. Изменение или новая неоднозначность — refusal/reinspect/reconfirm, не обновление frozen intent на лету; уже записанный intent без F остаётся Inspected, не Fenced и не разрешение Resume. Повторные чтения не заменяют исключение сторонних writers и не обещают атомарность без него.
- **После F:** Resume требует exact сохранённый marker/F/id/immutable intent и прежние phase/actual-bytes проверки. Историческое previous observation не пересоздаётся из нынешнего target/Mode и не переписывается; missing/NULL/corrupt/чужой F не восстанавливается из journal. Old unusable artifacts не становятся usable E от копирования.
- **Terminal import:** BackedOutEmpty остаётся non-NULL с прежними F/id/intent; старые marker/journal сохраняются. Новый restore-id, Inspect или Execute не разрешают reset/rebinding этого F. Следующий explicit import требует отдельно заново выбранного healthy provisioned NULL target, positive-empty destination, exact нового inspection/confirmation и обычного preflight; прежний BackedOutEmpty store не удовлетворяет этому условию. Разрешение стереть прежний fence или automatic destructive replay не добавляется.

## 12. Принятое уточнение: v1 actual rollback с historical source graph

Main принял этот mechanical ruling как закрытие carrier gap §10: optional bounded supplement внутри OutpostRollbackBridge, не новый root и не изменение game/operator policy. §1–11 и прежние v1 proof/same-boundary semantics сохраняются; это контракт для реализации Sol, не реализация или выполненные tests.

- **Additive carrier:** в OutpostRollbackBridge добавить optional SourceProvenance существующего типа OutpostSourceProvenance и SourcePathDigest на новых свободных tags. Graph/digest присутствуют только парой; digest связывает exact bounded encoded graph. Отдельное top-level metadata historical-source-provenance поле не требуется. Header и fresh metadata echo содержат один и тот же rollback-v1 Q с этим supplement; это один grant, а не совместные rollback/restore/rollback-from-view roots.
- **Actual canonical:** для rollback actual fresh S1[B1,e8]→e9 Q.CanonicalSnapshot остаётся exact physical proof S1(id1,rawHash1,original B1/e8); Q.SourceScope=B1/e8, Q.CurrentScope=fresh S2.Scope=B1/e9. В graph ActualSources[S1].Snapshot точно равен Q.CanonicalSnapshot, а его LocalFrontierDigest — Q.LocalFrontierDigest реального S1. Canonical не заменяется самым старым S0 и не relabel-ится; S1 XML/embedded bridge/hash/link неизменны.
- **Mirror того же Q:** AuthorizedViews[Q] имеет Kind=Rollback, exact Q operationId/transitionId/digest, Source.ActualSnapshotId=S1 (НЕ AuthorizedView R1), SourceScope/EffectiveScope/frontier, равные соответствующим Q fields. RegistryMap — exact before из Q.MutableRegistry и after тех же entries с единственной разрешённой сменой scope; PreviousCurrentScope — из того же committed rollback journal, доказывающего current e→e+1, не guessed target epoch. Это typed representation одного Q для traversal, не новая operation/authorization; mismatch двух представлений — refusal, не priority fallback.
- **Historical binding:** ActualSources[S1].HistoricalAuthorization указывает на exact transitionId/digest прежнего root R1, действительно embedded в original S1. Полная required closure R1.Source→actual/view→…→original actual S0[B0,…] сохраняет исходные scopes, maps, cut/manifest и digests. Путь carried B0 evidence: Q→actual S1→historical R1→…→actual source B0. Ancestor XML внутрь graph не копируются; R1 SourceScope/EffectiveScope/frontier не переписываются новым Q/S1 frontier. При следующем actual S2 rollback его HistoricalAuthorization точно связывает Q из original S2, а не превращает Q в повторный active grant.
- **Strict v1 validator:** прежние downloaded==CanonicalSnapshot, proof.Scope==SourceScope, SAME world/owner/generation/boundary и epoch-advance checks не менять. Supplement получает отдельную typed graph validation с exact binding всех Q fields, обязательным SourceCase=ActualSnapshotId именно S1 и полной closure. Actual-source запрет специального RollbackFromView validator сохраняется. Без supplement old v1 path/rules unchanged; malformed или required-but-missing supplement отказывает, не fallback к old-v1/Legacy.
- **Parser structure, не authority:** отдельная explicit supplement ветка может структурно допустить carried capture scope только по reachable Q→S1→historical closure. Она не превращает прежний same-boundary v1 branch в cross-boundary и не считает disconnected/arbitrary same-scope node достаточным. Presence graph/ref/scope не доказывает acceptance, terminal disposition или право replay; больше одного top-level active root по-прежнему отказ.
- **Server source/capture join:** проверить stored committed Q/journal, затем exact id/hash/scope/link/locator/real bytes S1 и самостоятельно разрешить original embedded root/graph S1 и все required ancestor bytes/transitions/maps/cuts. Echo graph/digest не authority: сравнить их с доказанным path. S2 carried capture должен совпадать целиком с original capture в exact accepted source/provenance, не только Scope/LocalOperationId; terminal disposition подтверждается stored receipts/journal/permanent ordinary negative fences. Добавленный/изменённый B0 capture, pending с подходящим scope, missing/conflicting required evidence — refusal, не drop/truncation/Legacy.
- **Download и fresh echo:** authenticated header Q + реальные parsed bytes S1 проходят прежний v1 actual checker; supplement дополнительно связывает S1.HistoricalAuthorization с действительно embedded historical root и closure. Только после этого допустим один scope-only main-thread registry plan. Fresh S2 содержит Q+supplement, НЕ скопированный top-level restore_bridge R1 и НЕ переупакованный RollbackFromView root. Historical graph nodes сами ничего повторно не rebase-ят и не заменяют physical proof.
