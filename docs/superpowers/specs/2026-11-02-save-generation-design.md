# Поколение сохранений после сброса колонии

## Цель

Административный reset не позволяет загрузить старый локальный сейв обратно на сервер. Восстановление после обрыва, включая первый сейв до установки pending-флага, продолжает работать для той же колонии.

## Контракт

- У игрока хранится `SaveGeneration` (Int64, начальное значение 0). Reset и пересоздание мира увеличивают его под существующей блокировкой хранилища при архивации версий. Обычное архивирование с восстановлением и rollback поколение не меняют.
- Протокол только расширяется: `LoginReply.save_generation = 12`, `SaveHeader.save_generation = 9`, `SAVE_GENERATION_MISMATCH = 60`. Старые клиенты и сейвы без поля относятся к поколению 0.
- Новый игровой компонент получает поколение при создании новой колонии. Он сохраняет его в XML (`rimlinkSaveGeneration`); загруженная игра сохраняет исходное значение. Поколение старого файла никогда не подменяется значением из нового login.
- Как обычная отправка, так и восстановление с диска используют поколение именно сохранения. Сервер повторно читает игрока и проверяет поколение непосредственно перед записью версии под `SaveFiles.PerStoreLock`, после получения потока. Reset и завершение уже начатой отправки поэтому сериализованы.
- При попытке восстановления старый локальный файл сохраняется отдельно с уникальным именем, pending-флаг очищается, затем загружается серверная версия или предлагается новая колония. Пользователь получает EN/RU объяснение. Несовпадение поколения — постоянный типизированный отказ. Временный отказ загрузки (в том числе rate limit) не должен убирать восстанавливаемый файл и pending-флаг. Неиспользуемый локальный кеш без pending при наличии серверной версии не разбирается: даже повреждённый кеш не мешает обычному download.
- Существующие данные мигрируют в поколение 0 без переписывания сейвов. После reset старый клиент получает отказ вместо восстановления удалённой колонии.
- Архив колонии хранит исходное поколение. После reset такой архив остаётся на диске, но не восстанавливается автоматически или через обычную команду restore: иначе сервер сам вернул бы сброшенную колонию в обход локальной проверки.

## Проверка

Сервер: reset с сохранённым старым файлом, повторные reset, отправка через границу reset, восстановление первого сейва того же поколения, схема и login. Клиент: XML с/без поколения, передача поколения, решение о старом локальном файле, временный отказ. Реальная игра: вход после reset с локальным файлом и свободным rate bucket, новая колония и повторный вход после её сохранения. Полный suite и сборки мода/компаньона обязательны перед релизом.
