# Rimlink — пакет целостности: dev mode, скачки богатства, рассказчик, выход в ОС

Дата: 2026-10-30. Статус: дизайн утверждён пользователем по частям (A, B, C); спека ждёт ревью.
Основа: отчёт `reports/Фичи мультиплеерных модов RimWorld.md` (раздел 1, пункт 1; таблица «Админка и анти-чит»; раздел 4),
спеки `2026-10-28-rimlink-economy-design.md` (эскроу, заморозка), `2026-10-28-rimlink-raids-visits-design.md` (богатство для
защиты от рейдов), `2026-10-29-rimlink-admin-panel-design.md` и `2026-10-29-rimlink-discord-bot-design.md` (панель, лента событий).

## 0. Цель и границы

Сервер сейчас верит клиенту больше, чем стоит: не-админ включает dev mode и спавнит вещи, колония на лёгкой сложности копит богатство
дешевле и несёт его на общий рынок и в рейды, а выход в ОС теряет всё, что сыграно после последнего автосейва. Пакет закрывает четыре
дыры:

1. Dev mode: не-админ не может включить его, пока подключён; сейв, в котором dev mode был включён, несёт флаг; сервер записывает его,
   показывает админам и замораживает экономику такого игрока.
2. Детектор скачков богатства по `WealthTotal` из заголовка сейва: первый порог предупреждает админов, второй замораживает экономику
   игрока.
3. Рассказчик и сложность мира фиксируются для всех колоний (новая колония, смена в игре, загрузка).
4. Выход в ОС (меню, Alt+F4, крестик окна) сохраняет колонию и выгружает её, как выход в меню.

Вне рамок: сценарий (в отчёте упомянут, в задачу не входит), автобан, серверная проверка содержимого сейва на спавн, защита от
модифицированного клиента, учёт серверного богатства в угрозе рейдов (отдельный пункт отчёта).

**Модель доверия.** Флаг dev mode и богатство сообщает клиент. Модифицированный клиент может солгать в обоих; пакет — линия для честного
клиента (dev mode, баги, эксплойты игры, дюп через мод). Клиентский запрет dev mode — первая линия, серверная запись и заморозка —
вторая, детектор богатства — третья: он ловит спавн и тогда, когда флаг dev mode не пришёл.

## 1. Настройки (`Integrity`)

Новый класс `IntegrityOptions` в `Hosting/ServerOptions.cs`, секция `Rimlink:Integrity`, валидируется при старте, каждый ключ описан
в `deploy/appsettings.example.json` и `docs/server-setup.md`.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `DevMode` | `AdminsOnly` | `AdminsOnly`: dev mode только у роли Admin; `Everyone`: у всех (серверы для своих, тестовые стенды). |
| `WealthWarnPerDay` | `20000` | Порог предупреждения: чистый прирост богатства в игровой день. 0 выключает. |
| `WealthFreezePerDay` | `100000` | Порог заморозки экономики игрока. 0 выключает. Если оба > 0, должен быть ≥ `WealthWarnPerDay`. |
| `StorytellerPolicy` | `Locked` | `Locked`: рассказчик и сложность мира у всех колоний; `Free`: как раньше, каждый выбирает сам. |

## 2. Заморозка экономики одного игрока

Сейчас есть только общая пауза торговли (`FreezeState`). Новая — у одного игрока, её ставит админ вручную или сервер автоматически
(dev mode, скачок богатства). Снимает только админ.

**Хранение.** `Player.EconomyFrozenAt` (`DateTime?`, null — не заморожен) и `Player.EconomyFreezeReason` (`string?`). Миграция
`Integrity` (вместе с колонками раздела 4).

**Протокол.** `ErrorCode.PLAYER_FROZEN = 38` в `common.proto` (после номеров веток сделок и модпака).

**Что отказывается.** `EconomyGate.RequireOpen(long playerId)` (новая перегрузка; старая без игрока остаётся для мест, где игрока нет)
проверяет сначала общую заморозку, потом игрока, и отказывает `PLAYER_FROZEN` с причиной. Её вызывают для инициатора:

- отправка посылки (`TransferService`), депозит и вывод (`WalletService`);
- выставление лота и покупка на рынке (`MarketService`);
- покупка в магазине при визите (`ShopService`);
- запуск рейда (`RaidService`, уже идёт через gate);
- сделки (`TradeService`, ветка сделок): открыть, изменить свою сторону, подтвердить — отказ, если заморожен любой из двух
  участников (обмен двигает вещи обеих сторон); отменить можно, вещи возвращаются владельцам.

Продавец заморожен — его лоты не показываются в `ListLots` другим игрокам и не покупаются (`PLAYER_FROZEN`); его магазин при визите
не продаёт. Это путь обналичить дюп.

**Что остаётся.** Доставки замороженному игроку (посылки, возвраты, лут — эскроу: ничего не теряется); снятие своего лота (вещи
возвращаются ему же посылкой); свои лоты он видит. Рейды и визиты к нему не меняются.

**Игроку.** При заморозке и при снятии сервер шлёт ему `Notice` (существующее событие) с причиной; отказ операции приходит обычной
ошибкой с текстом. Клиентских строк для этого не нужно: текст `Notice` приходит с сервера, как у остальных уведомлений сервера.

**Админу.** `AdminOperations.SetPlayerEconomyFrozen(actor, playerId, frozen, reason)` пишет аудит (`player-economy-freeze` /
`player-economy-unfreeze`) и публикует `admin.action`, как прочие операции. Зеркала:

- REST `POST /api/admin/players/{id}/economy` с телом `{frozen, reason}`;
- CLI `rimlink-tools admin player-freeze <id> [reason]` и `player-unfreeze <id>`;
- команды чата `/freeze <игрок> [причина]` и `/unfreeze <игрок>`;
- панель: на карточке игрока состояние (с причиной и временем) и кнопка; `PlayerCard` получает `EconomyFrozenAt`, `EconomyFreezeReason`.

## 3. Dev mode

### Клиент

`LoginReply.dev_mode_allowed = 10` (новое поле): сервер ставит его, если роль Admin или `Integrity:DevMode = Everyone`.

Пока сессия активна и dev mode не разрешён:

- при старте сессии (сразу после входа): запомнить `Prefs.DevMode`, выключить его через сеттер (ваниль при выключении снимает god mode
  и закрывает палитру) и сбросить `LudeonTK.DebugTools.curTool` (инструмент, оставшийся на мыши после одиночной игры);
- префикс на сеттер `Prefs.DevMode` отклоняет `true` с сообщением (`Rimlink.DevMode.Refused`);
- страховка каждый кадр в `RimlinkGameComponent.GameComponentUpdate`: dev mode включён (в обход сеттера) — выключить, сбросить
  инструмент;
- по окончании сессии (`RimlinkSession.End`) вернуть запомненное значение: одиночная игра не теряет настройку.

Отладочные действия категории Rimlink и инструменты моста, которым нужен dev mode, на таком сервере доступны только админам; для стендов
`Integrity:DevMode = Everyone`.

### Флаг в сейве

`RimlinkGameComponent.DevModeSinceUpload` (bool, `Scribe_Values` в сейве игры): ставится каждый кадр, когда `Prefs.DevMode` включён в
этой игре — в сессии или без неё (офлайн-игра файла мультиплеера тоже считается). Уходит в `SaveHeader.dev_mode = 8`
(`SaveMeta.DevMode`). После успешной выгрузки клиент сбрасывает его в памяти (следующий сейв пишет `false`).

Почему заголовок, а не значение из XML сейва: обе вещи пишет клиент, доверие одинаковое; `SaveValidator` останавливается на имени
фракции, а компонент игры лежит в конце файла — пришлось бы разбирать сотни мегабайт XML на каждую выгрузку.

### Сервер

`SaveVersion.DevMode` (bool) — флаг каждой версии, показывается админам в списке сейвов (REST `saves`, CLI, панель). Если флаг пришёл от
игрока, которому dev mode не разрешён (роль не Admin и `DevMode = AdminsOnly`), и игрок ещё не заморожен:

- аудит `integrity-devmode` (актор system), событие ленты `integrity.alert` с `kind = devmode`;
- заморозка экономики игрока с причиной «dev mode was on in save vN».

Сейв принимается в любом случае: прогресс не теряется.

## 4. Детектор скачков богатства

**База.** `SaveVersion.WealthTotal` и `SaveVersion.WealthItems` (новые колонки). Новый сейв сравнивается с текущей версией до записи.
Откат админа делает текущей другую версию и тем самым переносит базу. `SaveStore.Rollback` теперь ставит `Player.WealthTotal/Items` из
целевой версии (сейчас после отката они остаются от более новой версии, а их читают защита от рейдов и лимит лута); у версий до миграции
там 0, тогда значения игрока не трогаются.

**Формула.**

- `imported` — честно полученное между сейвами: посылки этому игроку с `DeliveredTick` в (`base.GameTick`, `new.GameTick`]; сумма
  серебра, `market_value_x100 × count / 100` вещей и стоимости пешек. У `PawnBlob` стоимости нет — новое поле
  `PawnBlob.market_value_x100 = 8`, клиент заполняет его из `pawn.MarketValue` (в старых посылках 0).
- `net = new.WealthTotal − base.WealthTotal − imported`.
- `days = max(1, (new.GameTick − base.GameTick) / 60000)`.
- `rate = net / days`.

Пропускается: первый сейв (нет базы); `new.GameTick ≤ base.GameTick`; `base.WealthTotal = 0` (версии до миграции и сейвы без
богатства); замороженный игрок.

**Реакция.**

- `rate ≥ WealthWarnPerDay` (> 0): аудит `integrity-wealth` с числами, событие `integrity.alert` с `kind = wealth-warn`.
- `rate ≥ WealthFreezePerDay` (> 0): то же с `kind = wealth-freeze` и заморозка экономики игрока с причиной
  («wealth +N/day in save vM»). Роль Admin не замораживается — только предупреждение.

Повтора нет: пока игрок заморожен, новые тревоги на него не создаются; каждый новый сейв сравнивается с предыдущим, поэтому один спавн
даёт одну тревогу.

**Где.** Чистый класс `WealthCheck` (`Application/Integrity/`) считает `rate` и решение по базе, новому заголовку, сумме импорта и
настройкам — без БД, тестируется отдельно. `IntegrityService` собирает данные (текущая версия, посылки), вызывает `WealthCheck` и флаг
dev mode, пишет аудит, ленту и заморозку. `SaveStore.Store` читает базу (текущую версию) до записи новой и вызывает сервис после
коммита (вне транзакции хранения: сбой проверки логируется и не отклоняет сейв).

## 5. Лента событий

Новый тип `integrity.alert` в `FeedTypes` (старые не меняются; бот, который тип не знает, его пропускает):

```json
{ "player": {"id": 7, "name": "Nova"}, "kind": "devmode | wealth-warn | wealth-freeze", "version": 12,
  "net": 250000, "days": 1.0, "rate": 250000, "frozen": true }
```

`net`, `days`, `rate` — null для `devmode`. Ручная заморозка идёт существующим `admin.action`.

## 6. Рассказчик и сложность

**Протокол.** `WorldParams.difficulty_values = 12` (bytes): Scribe-XML объекта `Difficulty` админа, сжатый zstd (как
`ItemBlob.scribe_xml_zstd`); заполняет `WorldSetup.CollectParams` при создании мира. `WorldInfo.storyteller_locked = 4`: сервер ставит его
по `Integrity:StorytellerPolicy`.

**Значения сервера** (`WorldSetup.ServerStoryteller()`): def рассказчика и сложности по имени; значения — из `difficulty_values`, если
есть, иначе `new Difficulty(def)`. Мир, созданный до этого поля, со сложностью Custom: фиксируется только def, значения не навязываются.
Нет def в модпаке клиента — предупреждение в лог один раз, ничего не меняется.

**Где фиксируется** (при `storyteller_locked` и существующем мире, для всех ролей):

1. `Page_SelectStoryteller` (новая колония): префикс на `DoWindowContents` каждый кадр переписывает поля `storyteller`, `difficulty`,
   `difficultyValues` значениями сервера и выводит подпись `Rimlink.Storyteller.Locked` — тем же приёмом, что
   `Patch_Page_CreateWorldParams`; тот же перенос в префиксе `CanDoNext`, который создаёт `Storyteller` из этих полей (клик и «Далее»
   не проскочат между кадрами).
2. `Page_SelectStorytellerInGame` (смена в игре): постфикс на `DoWindowContents` возвращает значения сервера и вызывает
   `Notify_DefChanged`, если def поменялся; подпись та же.
3. Загрузка своей колонии: на первом кадре `Playing` (не в `FinalizeInit` — правило загрузки из AGENTS.md; не в визите и не в зеркале
   живой сессии) расхождение исправляется: `def`, `difficultyDef`, `difficulty`, `Notify_DefChanged`, пересчёт стоимостей сложности, как в
   ванильном `Page_SelectStorytellerInGame.PreClose`. Строка в лог и сообщение `Rimlink.Storyteller.Applied`.

`rimlink/start_colony` выбирает Cassandra/Rough; при фиксации страница просто покажет значения сервера, инструмент работает дальше.

## 7. Выход в ОС

Сейчас: «Выйти в ОС» вызывает `Root.Shutdown` → `Application.Quit`, Alt+F4 и крестик окна — тоже выход Unity; ни то ни другое не
перехвачено, теряется сыгранное после последнего автосейва. Первый шаг реализации — воспроизвести на стенде (меню и
`CloseMainWindow()`, то есть сообщение WM_CLOSE, как крестик) и подтвердить потерю по версии и тику на сервере.

Исправление: один обработчик `Application.wantsToQuit`, подключается при загрузке мода, ловит все три пути. Если сессия активна и выход
ещё не идёт:

1. вернуть `false` (выход отменён);
2. в своей колонии (`Playing`, не визит): `GameDataSaveLoader.SaveGame` (постфикс запускает выгрузку); длинное событие
   `Rimlink.Flow.Uploading` ждёт её до 60 с; не успело — `Pending.Set()`, файл уйдёт при следующем входе;
3. `EndSession`, затем `Application.Quit()`; повторный вызов обработчика видит неактивную сессию и выход пропускает.

В визите и без загруженной игры: сразу `EndSession` и выход. Общая часть с `Patch_GenScene_GoToMainMenu` (сохранить, дождаться,
пометить, закончить сессию, продолжить) выносится в `SaveSync.SaveUploadAndEnd(Action then)`. Убийство процесса и краш не покрываются:
остаются автосейвы и флаг pending.

## 8. Строки

Английский и русский, `mod/Languages/*/Keyed/Rimlink.xml`: `Rimlink.DevMode.Refused`, `Rimlink.Storyteller.Locked`,
`Rimlink.Storyteller.Applied`. Тексты заморозки и тревог — серверные (`Notice`, аудит, лента).

## 9. Тесты

Сервер (xUnit, `tests/Rimlink.Server.Tests`):

- заморозка: каждая операция инициатора отказывает `PLAYER_FROZEN`; лоты замороженного продавца скрыты и не покупаются, магазин не
  продаёт; доставки и снятие своего лота работают; общая заморозка по-прежнему первой;
- `WealthCheck`: импорт вычитается, `days` не меньше 1, пропуски (первый сейв, тик назад, база 0, заморожен), пороги 0, админ без заморозки;
- `IntegrityService` через выгрузку: флаг dev mode у игрока и у админа, `Everyone`, нет повторной тревоги у замороженного, лента;
- откат переносит базу и `Player.WealthTotal`;
- валидация `IntegrityOptions`; схема (миграция); REST, CLI, команды чата, `PlayerCard`.

Клиент-ядро (`tests/Rimlink.Client.Tests`): `SaveMeta.DevMode` уходит в заголовок; `dev_mode_allowed` и `storyteller_locked` доходят до
состояния.

Игра (два экземпляра на s3, записи в `docs/manual-checklist.md`): dev mode у гостя отклоняется и возвращается после выхода; у админа
работает; флаг dev mode замораживает гостя (сервер с `Everyone` → `AdminsOnly`, или офлайн-игра файла); спавн отладкой у админа даёт
предупреждение, у гостя на сервере с `Everyone` — заморозку; страница рассказчика и смена в игре зафиксированы; загрузка колонии с другой
сложностью исправляется; выход через меню и крестик сохраняет и выгружает.
