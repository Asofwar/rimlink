# Rimlink — окно модпака, автовход после перезапуска, настройки модов сервера: дизайн

Дата: 2026-10-30. Статус: разделы утверждены в обсуждении, ждёт утверждения спеки.
Основа: `2026-10-28-rimlink-core-design.md` (вход, модпак, `Dialog_ModpackDiff`), отчёт `reports/Фичи мультиплеерных модов
RimWorld.md`, раздел 1 пункт (5) и таблица «Подключение и моды». Протокол только растёт, `ProtocolVersion` не меняется.

## 1. Задача и границы

Игрок, чьи моды не совпали с сервером, должен починить всё сам, одной кнопкой и без админа, а после перезапуска игры сам
попасть обратно на сервер. Сейчас сервер сравнивает моды только по `packageId` и версии, порядок загрузки и файлы не смотрит,
`allowed` ставится вручную, настройки модов не синхронизируются, а после перезапуска намерение войти теряется.

В спеке:

1. Окно расхождений по категориям: нет мода, версия, файлы, лишний, порядок, настройки; у каждой — что сделать и кто чинит.
2. Намерение войти переживает перезапуск игры, вход повторяется сам.
3. Переводы и моды без def, патчей и кода разрешены автоматически. Моды с def — никогда: блобы (пешки, вещи) несут def, и мод
   с новыми `ThingDef` у одного игрока даёт посылку, которую другой не распакует.
4. Настройки модов из белого списка сервера действуют у всех игроков; свои файлы игрока не трогаются.
5. Записки без кода: код подключения, каталог серверов, перенос одиночной колонии (раздел 11).

Не в спеке: оценка совместимости модов, автоскачивание модов не из Workshop, интерфейс белого списка в веб-панели (REST есть,
панель — отдельная задача).

Решения, принятые в обсуждении: несовпадение порядка — отказ во входе с исправлением одной кнопкой; настройки сервера —
через перезапуск, сервер запоминается; категория «файлы» — по хэшу `Defs/`, `Patches/`, `Assemblies/`; пароль на диск не пишется,
после перезапуска само открывается окно входа; сравнение — на сервере; общий код «состава мода» — в `Rimlink.Protocol`.

## 2. Протокол и хранение

`common.proto`, `ModRef` (клиент шлёт при входе и регистрации), новые поля:

| Поле | № | Смысл |
|---|---|---|
| `int32 position` | 3 | место в порядке загрузки клиента (0 — первый) |
| `string files_hash` | 4 | хэш состава мода (раздел 4); пусто — клиент старый, состав неизвестен |
| `bool has_defs` | 5 | в моде есть файлы под папкой `Defs` |
| `bool has_patches` | 6 | есть файлы под `Patches` |
| `bool has_assemblies` | 7 | есть файлы под `Assemblies` |

`auth.proto`: `LoginRequest.mod_settings = 6` и `RegisterRequest.mod_settings = 5` — `repeated ModSettingsHash`. Новое сообщение
`ModSettingsHash {string package_id = 1; string handle = 2; string hash = 3;}`: по одной записи на каждый класс `Mod` запущенных
модов; `handle` — имя класса, `hash` — SHA-256 действующего файла настроек (hex, нижний регистр) или `none`, если файла нет.

`modpack.proto`:

- `ModpackEntry.files_hash = 7` — хэш состава мода у админа; пусто — файлы этого мода не проверяются.
- `enum FixSide {FIX_SIDE_PLAYER = 0; FIX_SIDE_SERVER = 1;}`, `VersionMismatch.side = 4`.
- `FileMismatch {string package_id = 1; string version = 2;}`.
- `ModConfig {string package_id = 1; string handle = 2; bytes content = 3; string hash = 4;}` — настройки одного класса мода с
  сервера; `content` — XML файла настроек, `hash` — SHA-256 содержимого.
- `ModConfigList {repeated ModConfig configs = 1;}`.
- `ModpackDiff`: `bool order_differs = 5`, `repeated FileMismatch files = 6`, `repeated ModConfig configs = 7` (настройки сервера
  целиком, чтобы клиент применил их без сессии).
- Сервис `Modpack`: `rpc SetConfigs (ModConfigList) returns (Empty)` и `rpc GetConfigs (Empty) returns (ModConfigList)`, оба
  только для админа; пустой список выключает синхронизацию настроек.

`common.proto`, `ErrorCode`: `MODPACK_CONFIGS_INVALID = 32` — набор настроек отвергнут (размер, мод не в модпаке, мод раньше
Rimlink). Номера полей и кодов могут столкнуться с параллельными ветками: ветка, которая приходит позже, перенумеровывает при
перебазировании.

Хранение (EF Core, одна миграция `ModpackFilesAndConfigs`, тест схемы в `tests/Rimlink.Server.Tests/Storage`):

- `ModpackEntry.FilesHash` — nullable string.
- Таблица `ModpackConfigs`: `Id`, `PackageId`, `Handle`, `Content` (blob), `Hash`; уникальный индекс `(PackageId, Handle)`.

Лимиты (константы в `Protocol.Limits`): файл настроек ≤ 256 KB, всего ≤ 768 KB (настройки уходят в ответе на вход, а он не
больше `Limits.MaxMessageBytes` = 1 MB), не больше 64 записей.

REST: `GET /api/admin/modpack/configs` (scope чтения) возвращает `[{packageId, handle, hash, size}]` без содержимого;
`PUT /api/admin/modpack/configs` (scope админа) — `{configs: [{packageId, handle, contentBase64}]}`. CLI зеркалит (раздел 8).

## 3. Сравнение на сервере

`ModpackComparer.Compare(server, configs, client, clientSettings)`. Админ, как и сейчас, проверку не проходит. Пустой модпак
выключает всю проверку, включая настройки.

| Категория | Условие | Кто чинит |
|---|---|---|
| Нет мода (`missing`) | обязательного мода сервера нет у клиента | игрок: подписка или ссылка |
| Версия (`wrong_version`) | у записи задана версия, у клиента другая | `side`: сервер, если версия клиента **новее** (обе версии разбираются как числа через точку, клиентская больше); иначе игрок |
| Файлы (`files`) | версии равны или не заданы, `files_hash` есть у записи и у клиента, и они разные | игрок: проверить файлы или переподписаться; в тексте — «или админ импортировал другую копию» |
| Лишний (`extra`) | мода клиента нет в списке сервера | игрок: выключить мод или попросить админа разрешить |
| Порядок (`order_differs`) | обязательные моды сервера, которые есть у клиента, идут у клиента не в том относительном порядке | игрок: порядок сервера |
| Настройки (`configs`) | для записи `ModpackConfigs` у клиента есть `ModSettingsHash` с тем же `package_id`+`handle`, и хэш другой | игрок: настройки сервера |

Уточнения:

- **Авто-разрешение.** Мод клиента, которого нет в списке, не считается лишним, если клиент прислал `files_hash` (состав
  известен) и все три признака ложны: переводы, текстуры, звуки. Моды с dll, но без def (интерфейсные), разрешает только админ
  (`kind=allowed`, как сейчас). Признаки сообщает клиент; ложь в них — вопрос честности, а не безопасности: список модов клиент
  и так может подделать, блобы с чужими def отсекает `ModpackDefs`.
- **Новый клиент** — тот, у кого хоть один `ModRef` пришёл с `files_hash`; только для него проверяются файлы, порядок и
  авто-разрешение (у старого все позиции и признаки — нули).
- **Порядок** считается по позициям из `ModRef.position`. Разрешённые и лишние моды в порядок не входят. Порядок — отдельная категория и проверяется вместе
  с остальными: окно показывает и состав, и порядок.
- **Настройки** проверяются, только если клиент прислал хоть одну запись `mod_settings` (новый клиент шлёт всегда: у самого
  Rimlink есть класс `Mod`). Записи для модов, которых у клиента нет, пропускаются: мод уже в «нет мода». В `configs` уходят
  только несовпавшие записи, с содержимым.
- Ответ — как сейчас: `LoginReply` с пустым токеном и заполненным `modpack_diff`; любая непустая категория — отказ во входе.
- Старый клиент без новых полей: файлы, порядок, авто-разрешение и настройки для него не проверяются, остальное — как раньше.

## 4. Состав мода (`Rimlink.Protocol`, `ModContent`)

`ModContent.Scan(string modRoot) → ModContentInfo(string FilesHash, bool HasDefs, bool HasPatches, bool HasAssemblies)`, без
ссылок на игру; им пользуются игра (через `Client.Core`) и CLI импорта модпака.

- Учитываются файлы любого типа под каталогом с именем `Defs`, `Patches` или `Assemblies` (без учёта регистра) на любой глубине
  внутри мода: так одинаково считаются папки версий (`1.6/Defs`, `1.7/Assemblies`) и `Common`. Остальное (`About`, `Textures`,
  `Languages`, `Sounds`) не учитывается.
- Хэш: SHA-256 по файлам, отсортированным по относительному пути (нижний регистр, разделитель `/`, порядок ordinal); для каждого
  файла — UTF-8 пути, байт 0, длина (8 байт little-endian), содержимое. Мод без таких файлов даёт хэш пустого набора.
- Игра сканирует все запущенные моды один раз в фоне при старте (`ModContentCache` в `Client.Core`: задача запускается из
  конструктора `RimlinkMod`); `ModpackActions.RunningMods` ждёт результата перед первым входом.
- Хэш настроек считается при каждом входе: для каждого класса `Mod` запущенных модов — SHA-256 файла, который вернёт
  `LoadedModManager.GetSettingsFilename` (через подмену из раздела 7, если она действует), или `none`.
- `rimlink modpack import` той же функцией заполняет `files_hash` у каждой записи по найденной папке мода.

## 5. Окно расхождений и «Исправить и перезапустить»

`Dialog_ModpackDiff` показывает категории в порядке: нет мода, версия, файлы, лишние, порядок, настройки. У каждой — заголовок
с числом, строка «что сделать» и строки модов; у версии подсказка своя на строке: «обновите мод» (`side=player`) или «на
сервере старая версия — напишите админу» (`side=server`). Порядок и настройки — одна строка без списка модов (настройки — со
списком модов, чьи настройки будут взяты с сервера). Решение «какие категории и в каком порядке» — чистая функция в
`Client.Core` (`ModpackDiffView`), окно только рисует.

Кнопки: «Подписаться на недостающие», «Открыть ссылки», «Исправить и перезапустить», «Закрыть».

«Исправить и перезапустить»:

1. Если подписанные моды Workshop ещё качаются (`SteamUGC.GetItemState`: нет `Installed` или есть `Downloading`/`NeedsUpdate`),
   кнопка ждёт и показывает «Загрузка: N модов…»; моды по ссылке игрок ставит сам, перезапуск им не мешает.
2. Записывает настройки сервера и делает его набор активным (раздел 7), если в расхождении есть `configs`.
3. Ставит список и порядок сервера: `ApplyServerOrder` (бэкап `ModsConfig.rimlink-backup.xml`, лишние моды выключаются —
   авто-разрешённые моды клиента остаются включёнными в конце списка).
4. Записывает намерение войти (раздел 6).
5. `GenCommandLine.Restart()`.

## 6. Намерение войти и автовход

`JoinIntentStore` в `Client.Core`: файл `<SaveData>/Rimlink/join-intent.json` — `{host, port, display, login, createdUtc}`
(`login` — только для аккаунта с паролем).

- `Save(intent)` пишет файл; `Take(now)` читает, **удаляет** файл и возвращает намерение, если ему не больше 15 минут; иначе null.
  Удаление при чтении даёт ровно одну попытку: если после перезапуска расхождение осталось, окно покажется снова, а цикла
  перезапусков не будет.
- При первом показе главного меню (`MainMenuPatch`) игра вызывает `Take` и, если есть намерение, запускает `LoginFlow.Run` на этот
  сервер. Steam-аккаунт входит молча; для аккаунта с паролем сразу открывается окно входа с подставленным логином. Пароль на
  диск не пишется.
- Пин сертификата уже сохранён с прошлого входа: вопроса об отпечатке не будет.

## 7. Настройки модов сервера

Белый список — это записи `ModpackConfigs` на сервере (раздел 8): моды, чьи настройки общие (например множители очков рейда).

**Подмена пути.** RimWorld читает и пишет настройки мода через `LoadedModManager.GetSettingsFilename(modIdentifier, handle)`,
где `modIdentifier` — имя папки мода (у Workshop — номер), а файл — `Config/Mod_<папка>_<класс>.xml`. Моды обычно читают
настройки в своём конструкторе (`LoadedModManager.CreateModClasses`). Патч `Patch_LoadedModManager_GetSettingsFilename` (postfix)
для пар `(packageId, handle)` из активного набора возвращает `<SaveData>/Rimlink/server-settings/<сервер>/Mod_<packageId>_<handle>.xml`.
`packageId` находится по имени папки среди `ModLister`. Патч ставится вручную в конструкторе `RimlinkMod` отдельным экземпляром
Harmony — до `PatchAll` из `[StaticConstructorOnStartup]`, который выполняется уже после конструкторов модов.

**Активный набор** — `<SaveData>/Rimlink/server-settings/active.json`: `{server, display, mods: [{packageId, handle}]}`.

- Читается один раз в конструкторе `RimlinkMod`; действует до выхода из игры.
- «Исправить и перезапустить» кладёт файлы `configs` из расхождения в папку сервера и записывает `active.json` с этим сервером.
- Следующие запуски сразу стартуют с настройками запомненного сервера: перезапуск нужен один раз, пока сервер не сменит
  настройки или игрок не пойдёт на другой сервер (тогда снова категория «Настройки», и активным становится тот сервер).
- Свои файлы игрока не читаются и не пишутся. Настройку из набора, изменённую в игре, игра пишет в копию сервера; при
  следующем входе хэш не совпадёт, и категория «Настройки» вернёт серверное значение.
- Под кнопкой «Мультиплеер» в главном меню — строка «Действуют настройки модов сервера X: A, B» и кнопка «Свои настройки»:
  удаляет `active.json` и предлагает перезапуск. Одиночная игра в том же запуске идёт с настройками сервера; эта строка —
  единственное напоминание.

**Порядок загрузки.** Подмена срабатывает только для модов, чей класс создаётся после конструктора Rimlink, то есть для модов
ниже Rimlink в списке. Поэтому сервер отвергает набор настроек мода, который в модпаке стоит выше `asofwar.rimlink`
(`MODPACK_CONFIGS_INVALID`), а «порядок сервера» у игрока ставит Rimlink туда же, куда админ.

## 8. Инструменты админа

- `rimlink modpack configs import --config-dir <путь к Config> --mods-dir <папки модов>… --mod <packageId>… --server --token`:
  по `About.xml` в папках модов сопоставляет `packageId` с именем папки, берёт все `Mod_<папка>_*.xml` этих модов, печатает список
  файлов и предупреждение «в настройках бывают секреты (токены Twitch и т.п.) — проверьте файлы перед загрузкой» и загружает
  их (`PUT /api/admin/modpack/configs`). `--clear` загружает пустой набор. `--dry-run` только печатает.
- `rimlink modpack configs list` — что сейчас синхронизируется (`GET`).
- Сервер проверяет набор в `ModpackService.SetConfigs`: лимиты размера, мод есть в модпаке и стоит ниже `asofwar.rimlink`;
  иначе `MODPACK_CONFIGS_INVALID` с текстом причины. Набор заменяется целиком в одной транзакции; запись в лог админа.
- `rimlink modpack import` дополнительно заполняет `files_hash` (раздел 4).

## 9. Ошибки и пограничные случаи

- Скан модов упал (нет доступа к файлу): мод отправляется без `files_hash`, сервер не проверяет его файлы и не авто-разрешает.
- Файл настроек сервера не удалось записать при «Исправить и перезапустить»: окно показывает ошибку, перезапуска нет.
- `active.json` повреждён или папки сервера нет: подмена не включается, в лог одна строка; вход покажет категорию «Настройки».
- Мод из набора выше Rimlink у игрока (порядок не исправлен): подмена для него не сработает, хэш не совпадёт, вход покажет и
  «Порядок», и «Настройки»; «Исправить и перезапустить» чинит оба.
- Админ сменил модпак или настройки, пока игрок в игре: проверка — только при входе, как сейчас.
- Workshop недоступен (Steam выключен): «Подписаться» ничего не делает (как сейчас), «Исправить и перезапустить» не ждёт загрузок.

## 10. Проверка

- Сервер (xUnit): каждая категория по отдельности и вместе; `side` у версии (новее, старее, нечисловые версии); файлы с пустым
  хэшем с любой стороны; авто-разрешение по признакам и его отсутствие без `files_hash`; порядок (совпадает, переставлен,
  разрешённые моды в середине, позиции не присланы); настройки (совпали, разные, мод отсутствует, старый клиент); лимиты и
  `MODPACK_CONFIGS_INVALID` (размер, мод не в модпаке, мод выше Rimlink); REST и CLI настроек; схема миграции.
- Protocol и ядро (xUnit): `ModContent.Scan` на временных папках (папки версий, регистр, файлы вне учтённых папок не меняют хэш,
  порядок обхода не влияет); `JoinIntentStore` (свежее, старое, повторное чтение пусто); `ModpackDiffView`.
- Игра, BT-стенд, два экземпляра: модпак загружен CLI из `ModsConfig` копии; у гостя по очереди — выключен мод, переставлен
  порядок, правка файла в `Defs`, лишний мод с def, мод-перевод, изменена настройка мода из белого списка. Каждый раз — окно с
  нужной категорией, «Исправить и перезапустить», автовход, после перезапуска категории нет. Перезапуск уводит процесс из-под
  GABS: игра переподключается к GABS через `games_connect` (или стартует заново, и тогда автовход проверяется по логу сервера).
  Запись прогона — в `docs/manual-checklist.md`.

Документация: `player-guide` (категории, автовход, настройки сервера, «Свои настройки»), `server-setup` (белый список, секреты,
Rimlink выше синхронизируемых модов, CLI), `AGENTS.md` (если меняются инструменты BridgeTools), чеклист.

## 11. Расширение (записки, без кода в этой работе)

**Код подключения.** Строка `rimlink://<хост>:<порт>?fp=<sha256 сертификата>&name=<имя>`; в руки игрокам — короткий
base64url-вариант той же строки. Сервер показывает код на публичной странице статуса и в панели админа. В игре в списке
серверов — «Добавить по коду»: адрес, имя и отпечаток берутся из кода, пин сохраняется сразу, ручной сверки отпечатка при первом

код показывает имя сервера и отпечаток перед сохранением.

**Каталог серверов.** Нужна общая служба, которую кто-то держит и модерирует. Возможный вид: сервер по желанию админа шлёт
сердцебиение (имя, адрес, онлайн, ссылка на модпак) на настраиваемый URL каталога, игра показывает список с этого URL. Отложено,
пока нет хозяина у такой службы.

**Перенос одиночной колонии.** Мир Rimlink заблокирован по параметрам, а одиночная колония живёт в своём мире. Реалистичный
путь — перенести карту дома и пешек в новое поселение на свободном тайле мира сервера (хирургия сейва: карта, пешки, вещи, без
фракций и квестов чужого мира), с проверкой def по модпаку и подтверждением админа. Сложность высокая, ценность низкая: не сейчас.
