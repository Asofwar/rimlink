# Приёмка доставки модпака без Steam

Реализованы упаковка и публикация подготовленного набора через CLI, доступ до входа, докачка, проверка ZIP, установка с журналом и откатом, полный снимок общих настроек и один restart/rejoin. Административный обход модпака сохранён. Работа находится в `asofwar/gog-modpack-download` поверх `45a188b`; публикация и обновление рабочего сервера не выполнялись.

## Автоматические проверки

Проверяются реальные fixture-сервер, CLI-библиотека, HTTP и файловые операции:

- CLI pack/publish → приватный bootstrap/access → manifest/settings → докачка206; сервер200 вместо206 корректно заменяет частичный файл;
- полный SHA-256 архива и `contentHash` всех файлов; прежний gameplay `FilesHash` остаётся совместимым;
- разные Textures при одинаковом gameplay hash не считаются точной чужой копией;
- полный новый ModHandle получает настройки до имитации единственного restart; обычный игрок затем получает session token;
- отказ прав/согласия, смена требований, unpublish, повреждение опубликованного архива, лимиты запросов;
- unpublish прерывает уже начавшийся **HTTP** stream до локального трёхсекундного deadline;
- быстрая повторная публикация сохраняет текущий и предыдущий пакеты; старые бесхозные файлы после restore удаляются без удаления посторонней заметки оператора;
- миграция с опубликованной схемы `SaveGeneration` сохраняет мир и модпак;
- traversal, ZIP links/collisions/bombs, вложенные Config/.git и устройства CONIN$/CONOUT$ отвергаются;
- чужие папки, изменённый конфиг/backup и загруженный managed root не перезаписываются;
- оригинальный ModsConfig сохраняется до первого изменения; отсутствие исходного файла тоже восстанавливается;
- четыре файловых checkpoint прерванного commit восстанавливаются новым экземпляром установщика; это имитация остановленного процесса, не физический kill в выбранную микросекунду;
- rollback на настоящих разных томах D: (игра) и C: (профиль) прошёл;
- отмена после последней записи откатывает установку; межпрофильный lock и одноразовый intent проверены.

После единого обзора и прохода исправлений: полный suite **1550 passed** за137.7s; дополнительный тест global pending-marker — **1 passed**. Linux/WSL на2 CPU: **147 passed**. Мод0.8.0 и companion собираются. [Замечания и их закрытие](2026-11-03-gog-modpack-review.md).

## Настоящий игровой прогон

Стенд: `D:/Build/rimlink-gog-acceptance-20261102`, отдельная копия RimWorld1.7, собственный профиль, TLS-сервер25640 и GABS8769. Рабочий Docker-сервер, Steam, подписки и пользовательская игра не изменялись.

Steam обнаруживает глобальные Workshop-копии даже из отдельного каталога игры. Native UI правильно отказал при двух Harmony и двух Rimlink, показав оба пути. Убрана только созданная для стенда копия Harmony. Подписанная пользователем Rimlink не удалялась и не менялась.

Для положительного пути **только метаданные локального стенда** имеют packageId `test.rimlinkclient`; продуктовый `mod/About/About.xml` остаётся `asofwar.rimlink`. Неактивная каноническая Rimlink разрешена в тестовой коллекции, чтобы сохранить штатную политику настроек. Это ограничение приёмки: такой стенд доказывает общий native workflow, но не заменяет настоящий GOG-прогон с каноническим packageId.

Пакет из Harmony, локальной Rimlink и собственного тестового `test.rimlinkdelivery`: загрузка6.1МиБ, после распаковки11.8МиБ. Проверены:

1. EN/RU preview, числовые объёмы, reuse/install, отдельные согласия на моды и настройки; кнопка установки недоступна без обоих согласий.
2. Отмена preview: нет managed-папки, журнала и restart.
3. Установка новой DLL мода с прежде отсутствующим `DeliverySettingsMod` в отдельную верхнюю папку Mods.
4. Один настоящий restart: PID67916 →69820. Другую игру для восстановления управления не запускали.
5. В первом запуске `00:24:49`: `[DeliveryAcceptance] new handle read shared settings: enabled=True`.
6. Повторный вход обычного `gogtest`, роль0 в SQLite, затем экран выбора сценария новой колонии.
7. В `00:31:07`: `[Rimlink] downloaded modpack verified after restart and login`. Journal, pending marker и intent отсутствуют.

GABS потерял runtime claim после vanilla restart дочернего процесса. Тот же PID69820 доведён до обычного входа через CUA Driver; итог независимо подтверждён SQLite, журналом и логом. Новый restart для восстановления моста не делали. Скриншоты EN/RU просмотрены.

Исходные ответы и изображения: папки `responses`/`shots`, `native-assertions.json` в стенде. Личные Prefs не заявлены как побайтно совпавшие в native-прогоне: предварительная команда Get-FileHash была недоступна. Сохранность Config/outbox проверена файловыми fixture-тестами.

После первого прогона дополнены отказы ZIP и GC пакетов, а после rollback добавлен обязательный ручной restart перед входом. После итогового обзора проведён ещё один native-прогон финальной сборки:

- Обычный аккаунт получает mismatch до установки отсутствующего тестового маркера; пакет установлен штатным экраном, parent63440 → child5388.
- В snapshot есть `DeliverySettingsMod` и `OptionalClass`; `test.optionalsettings` не установлен и не активен.
- После commit в собственную тестовую папку добавлен файл Textures вне gameplay hash. Серверный comparer допускает credential check, но клиент показывает «Вход остановлен; резервные копии сохранены» и не начинает Session/outbox. Journal остаётся AwaitingRestart, intent потреблён, повторного restart нет.
- Удалён только намеренно добавленный тестовый файл. Ручной вход того же обычного игрока в **том же PID5388** успешен; `01:41:37` — verified и NewColony. Journal/pending отсутствуют, полный snapshot всё ещё содержит оба handles. Это также подтверждает исправление неактивного Allowed-мода в настоящем runtime.
- Исходные утверждения — `final-native-assertions.json`, изображения `final-mismatch-blocked.png` и `final-verified-no-second-restart.png`. Первый прогон сохранён в `run1/`.

Один предварительный вызов dev-tool меню завис; до установки перезапущен только собственный клиент, затем использован рабочий путь mismatch. Он не включён в утверждение о единственном restart установки. Физический ввод CUA иногда был no-op; успешность отмечалась только по новому экрану, логам и файлам.

## Незакрытые границы

- GOG-копии нет — пользователь это подтвердил. Настоящий GOG без Steam не проверен.
- Физическое завершение процесса в момент межтомного rename, реальный disk full и maximum-size2ГиБ package не прогонялись.
- Все четыре замечания единого обзора исправлены и проверены. Слияние, push, release, рабочий сервер и Workshop не изменялись.
