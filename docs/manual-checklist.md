# Ручной чек-лист (то, что автотесты не покрывают)

Отмечать при каждом релизе. Прогон 2026-10-28 (RimWorld 1.7.4990, локальный сервер, два аккаунта на одном
клиенте): отмечено `[x]`; `[ ]` — не проверялось в этом прогоне.

## Сервер

- [x] **Импорт модпака.** `rimlink-tools modpack import --from <Config>/ModsConfig.xml --mods-dir <RimWorld>/Data <RimWorld>/Mods <workshop>/294100 --server https://host:25560 --token <Admin:ApiToken> --insecure`
      (сначала с `--dry-run`): в списке есть все активные моды с версиями, у Workshop-модов заполнен `workshop_id`.
- [x] **Лимит неавторизованных соединений.** Открыть 6 раз `openssl s_client -connect 127.0.0.1:25560 -alpn h2` без данных:
      шестое соединение закрывается сразу, первые пять закрываются через 30 с (`login timeout`).
- [ ] **Steam-вход с настоящим билетом.** Нужен Web API key (https://steamcommunity.com/dev/apikey) в `Auth:SteamWebApiKey`.
      Клиент получает билет через `SteamUser.GetAuthSessionTicket` и вызывает `Auth.Login` — ожидается токен сессии.
      Если Steam отвечает `Invalid ticket` для ключа обычного (не издательского) аккаунта — записать это в `docs/server-setup.md`
      как требование и держать `Auth:AllowPassword=true` как запасной путь.
- [x] **Admin CLI против живого сервера.** `rimlink-tools admin online|broadcast|shutdown --server https://127.0.0.1:25560 --token T --insecure`
      отвечает (HTTP/1.1 на основном порту).

- [x] **Модпак-дифф.** Задать модпак на сервере, убрать один мод у клиента: диалог со списком, «Использовать порядок сервера» пишет `ModsConfig.xml` (бэкап `ModsConfig.rimlink-backup.xml`).
- [x] **Вход с другого места.** Второй клиент тем же аккаунтом: первый получает «вход с другого места» и уходит в меню без переподключения.
- [x] **Два клиента онлайн.** Второй экземпляр игры (`RimWorld.exe -savedatafolder=<папка>`): оба видят друг друга в «Игроки», личные сообщения доходят.

- Найдено и исправлено:
  - после «входа с другого места» вытесненный клиент оставлял сейв с флагом выгрузки и при следующем входе затирал им сейв,
    сыгранный на другом устройстве (`v7 tick 8179` → `v8 tick 1652`). Теперь сессия заканчивается сразу, флаг снимается,

  - после переподключения клиент не сообщал серверу, что он в своей колонии (`atHomeSent`), и живые приглашения к нему
    отклонялись «not online at their colony» до перезахода; проверено перезапуском сервера: `SetAtHome` уходит, сессия стартует;
  - `Live:GuestPauses` / `Live:GuestPauseSeconds` ничего не меняли (в клиенте были константы 10/60); теперь приходят в `LiveSession`,
    проверено: HUD гостя `pauses 0/3` при `GuestPauses=3`;
  - пауза гостя (пробел, кнопка паузы) не доходила до хозяина: `TogglePaused` пишет поле скорости мимо сеттера, а патч был только
    у хозяина; теперь в зеркале она уходит приказом, пауза хозяина гостю не снимается; проверено: хозяин встаёт на паузу, пробел снимает,

## Связи при возвращении (ветка `asofwar/cool-austin-217d7c`, спека `2026-10-29-rimlink-relations-on-return-design.md`)

Лог: `relations recorded for <пешка>: <n>` при уходе, `relations: <пешка> <связь> <вторая> <исход>` при возвращении. Строки загрузки блоба
`Could not resolve reference … Thing_Human…` и `has relation "X" with null pawn` остаются: журнал добавляет связи сразу после них.

- [ ] **A. Dev round-trip.** Колонист с супругом, ребёнком и связанным животным → «Blob round-trip selected thing»: `recorded`, по строке
  `Restored` на связь, нет `Tried to add the same relation twice`; вкладка «Социальное» у колониста, супруга, ребёнка, связь у животного;
  после сохранения и загрузки — то же.
- [ ] **B1. Отказ сразу.** Перевод женатого колониста забаненному игроку → отказ → колонист на месте, брак у обоих.
- [ ] **B2. Отказ при повторе outbox после перезагрузки.** Неотвеченный перевод, сохранение, выход, бан получателя, вход → отказ → капсула
  с колонистом, брак у обоих.
- [ ] **C. Умерший супруг.** Супруг убит и похоронен, пока колониста нет → по возвращении связь с умершим (`Restored`, не `OtherGone`).
- [ ] **D. Старый id.** После любого возвращения: сохранение, загрузка → пешка в панели колонистов, выбирается, нет ошибок про её id.
- [ ] **E. Пара из Real-рейда.** Муж и жена в одном рейде, ребёнок дома; выжившие домой посылкой `RaidReturn` → брак у обоих, у ребёнка
  оба родителя; так же для гостей после live-сессии.
