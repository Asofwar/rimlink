# Обновление сервера и клиентов

Применимость: Rimlink 0.10.0 · RimWorld 1.7 · протокол 1.

## Как пользоваться {#usage}

Перед заменой на 0.9.2 проверьте точный runtime 10.0.14 для сервера и CLI. Для незавершённого pre-DDL restore plan сохраните исходный executor и его изолированный квалифицированный runtime 10.0.13. Executor 10.0.14 не подменяет замороженный witness. Доказанное post-schema продолжение может читать старый witness без исполнения DDL; соблюдайте процедуру восстановления аванпостов.

1. Прочитай изменения релиза и сверяй сервер/мод/набор модов.
2. Объяви обслуживание, заверши сессии штатно и сделай согласованную резервную копию. Запиши используемую версию и настройки.
3. Проверь обновление на отдельной копии данных. Миграции EF применяются при старте; сохраняй старый snapshot до проверки.
4. Замени сервер, затем обнови клиентский мод с закрытой игрой. Пересобери/перепубликуй разрешённый набор при изменении требований.
5. Проверь вход, загрузку/отправку сейва, почту и модпак. Открой доступ после успешной проверки.

При неудаче останови новый сервер. Возвращай совместимый комплект старого сервера и проверенной копии данных; простая замена бинарника после миграции не гарантирует совместимость.

## Контрольная точка и решение о возврате {#update-proof}

До обновления зафиксируй бинарники/образ по версии или digest, конфигурацию, коллекцию и согласованный backup. На тестовой копии проверь миграции, вход, сейв, replay/почту и TLS. Изменение версии мода может требовать нового импорта коллекции и нового разрешённого ZIP, а не только замены server DLL.

При отказе останови новую версию и не пускай клиентов на две копии мира. Возвращай согласованную пару старые бинарники + совместимый backup данных, не один executable поверх уже мигрированной базы. Запиши, какие операции успели совершиться после checkpoint: они могут потребовать ручного согласования.

Завершение обновления — повторная приёмка игрового входа и сохранения, а не только успешный запуск контейнера.

## Ограничения и безопасность {#limits}

Версия протокола меняется только при несовместимом контракте, но одинаковый протокол не отменяет требований к модам. Не обновляй общий каталог игры чужого сеанса. Публикация пакета требует отдельного решения оператора.
