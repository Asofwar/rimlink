# Вклад и сопровождение wiki

Применимость: Rimlink 0.10.0 · RimWorld 1.7 · протокол 1.

## Как пользоваться {#usage}

Прочитай инструкции репозитория, status/diff и спецификацию области. Сохраняй чужие изменения. Здесь Astra пишет спецификации/планы и одно итоговое review, основная Sol реализует код и исправления. Для значимых изменений: согласованный дизайн → план → тесты/реализация → один итоговый обзор → проверки.

Wiki — часть готовности задачи. При изменении возможностей, ошибок поведения, config/CLI/API, установки, эксплуатации и восстановления обнови полные RU/EN статьи, навигацию и reference inventory в той же задаче. Укажи sourcePaths, подними contentRevision обеих версий и manifest; при отсутствии влияния на docs дай конкретное обоснование. Source snapshot не разрешает молча оставить устаревший перевод.

Запусти доступные проверки и отчитайся о страницах/результатах/ограничениях. Не включай секреты и внутренние handoff-заметки в опубликованный корпус. Коммит проверяет реальную Git-личность; push, PR и deploy требуют отдельного разрешения.

## Готовность задачи включает документацию {#contribution-dod}

До реализации найди feature-spec и статьи из sourcePaths manifest. Новая функция требует объяснения игроку и админу, а изменение API/config — обновления reference и источникового snapshot после ручной сверки. Не обновляй digest только ради зелёного CI.

Для каждого предметного topic сохрани вопрос RU/EN, anchor и точный источник. Проверь паритет и исходную базу drift, затем сборку/ссылки/браузер. Исключение docs-impact привязано к текущему base, hash изменённых файлов и reviewer; старое объяснение не разрешает будущий пропуск документации.

В отчёте назови страницы, выполненные команды и ограничения. Правка исходников wiki сама не разрешает deploy: Git identity, staged/secrets gate и команда пользователя остаются отдельными.

## Ограничения и безопасность {#limits}

Датированные планы и результаты проверки — исторические материалы, не обещания текущей работоспособности. Релизная версия синхронизируется между Directory.Build.props, ClientInfo.Version и About.xml; protocol меняется только при несовместимости. Публикация Pages запускается вручную, не обычным push.
