# Хранилище и эскроу

Применимость: Rimlink 0.8.1 · RimWorld 1.7 · протокол 1.

## Как пользоваться {#usage}

Изменение схемы — EF Core migration и schema test. Команда: dotnet ef migrations add &lt;Name&gt; --project src/Rimlink.Server (без -nologo). Миграции применяются при запуске.

SaveFiles единственный знает имена: &lt;n&gt;.rws.zst — полный сейв, &lt;n&gt;.d&lt;k&gt;.zst — delta к base-&lt;k&gt;.rws.zst. Size/Sha256 описывают полный контент даже при delta на диске. Только OpenCurrent гарантирует восстановление актуальной версии; нельзя предполагать наличие полного файла для любой старой записи. Проверяй hash до доверия существующему файлу.

Эскроу хранит отправленные предметы/пешек/серебро до исхода, возврат идёт почтой. Состояние live меняется под LiveStateLock с чтением строки внутри lock. Backup держит PerStoreLock и save-storage.lock при снимке БД и упаковке сейвов.

### Поколение колонии и эпоха записи

`SaveGeneration` меняется при reset: старый локальный сейв не должен стать первой версией новой колонии. `SaveWriteEpoch` меняется при административном rollback внутри того же поколения: прежняя сессия/исходящие операции не должны перезаписать выбранную администратором временную линию. Номер версии сейва — отдельный последовательный идентификатор, не один из этих счётчиков.

Upload сверяет generation/epoch заголовка, recovery proof и эпоху начатой сессии; несовпадение даёт SaveGenerationMismatch или SaveWriteEpochMismatch. После rollback клиент должен получить актуальные authority и снимок, а не повторять устаревший outbox с переписанными метаданными. Проверяй тестом: начни старый upload, выполни rollback, затем продолжи upload — он обязан быть отвергнут без изменения текущего сейва.

## Ограничения и безопасность {#limits}

Не удаляй lock-файл. Полный файл со spare delta может быть незавершённым rebuild: сначала сверить raw содержимое и metadata. zstd prefix и input не должны быть одним массивом. Не коммить *.db и каталоги данных.
